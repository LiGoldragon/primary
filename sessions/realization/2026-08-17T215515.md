All three subflows converged. The live Chroma 0.2.3 CLI parses its sole typed Dotos argument into `Request` before opening the Unix socket. `(SetTheme Dark)` is the retired NOTA parenthesized-list form; it cannot be viewed as the required Dotos application and therefore produces the reported `ExpectedDelimited` error without contacting the daemon. The canonical current request is `SetTheme.(Dark)` (or `SetTheme.(Light)`), which the live implementation parses and serializes into the daemon's length-prefixed rkyv `Request` archive.

The causal source change is Chroma commit `1e36e0ece221` on 2026-07-31, which intentionally migrated the text boundary from NOTA to DOTOS and changed implementation, README, tests, and sandbox from `(SetTheme Dark)` to `SetTheme.(Dark)` together. Current authored repositories contain no stale SetTheme caller. CriomOS-home/Noctalia calls only unit request `GetSolarClock`, and Pi's theme integration uses a separate line protocol. The old form remains in current Zsh history, but the provenance of the psyche's present invocation beyond stale human/session knowledge is unknown.

Proposed terminal repair: migrate the invocation and any future discovered caller to the canonical typed object; keep the strict Request parser; do not add a compatibility grammar, alternate envelope, or daemon/wire change. The focused witness is Chroma's Request decode/encode/rkyv test, and the durable end-to-end witness is `nix build .#checks.x86_64-linux.sandbox-terminal`. The only open design fork is whether explicit rejection of the obsolete form deserves its own regression witness; positive canonical coverage already exists. No source or deployment state was changed, and no psyche ruling landed.
