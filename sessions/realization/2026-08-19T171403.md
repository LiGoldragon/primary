## Harness finding

The current harness API does not expose whether a particular session has a live connected harness while its agent is idle. Its status query reports daemon actor/readiness state only; it has no session identity, provider connection, lease, heartbeat, idle state, or observation timestamp. Claude-owned session metadata can be correlated with a live process and Unix socket endpoint as a provider-specific approximation, but a socket node is not evidence of an established peer connection and the artifacts can be stale. A provider-neutral connected-and-idle predicate remains unimplemented. Investigation bead `primary-lix` is closed with the source/runtime evidence and error boundaries.
