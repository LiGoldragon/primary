## No-logout design fork

The browser association is already effective in the current session: the stale system `xdg-open` uses the desktop portal, whose HTTP/HTTPS defaults now resolve to Chrome. Only the selection of handlr as the opening engine remains stale.

A complete declarative no-logout alternative is to project the same handlr-backed wrapper into the NixOS system profile with higher package priority than xdg-utils. Existing processes already search `/run/current-system/sw/bin`; a normal live `Deploy.Host` activation changes that stable profile path, so the next invocation resolves handlr without changing process environments, ending niri, or rebooting. The wrapper should be one exported package consumed by both Home and NixOS, not two implementations. This makes the opening engine system-wide and therefore requires an explicit psyche ruling before implementation.

Partial alternatives are insufficient: importing PATH into systemd/D-Bus affects only future service-launched applications; niri config reload can override only future niri children and requires a complete literal PATH; neither changes existing shells or all application launch paths.
