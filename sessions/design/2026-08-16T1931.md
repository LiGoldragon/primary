Researched how the field's AI coding flows read and analyze code
(three web passes: influencers, general tooling, Rust-specific).
Five camps: agentic grep (Claude Code, Amp, most CLIs), grep plus
trained embeddings (Cursor alone), deterministic SCIP code graphs
(Sourcegraph), tree-sitter repo maps (Aider), language-server
inheritance (Junie, Zed, Serena) — plus compiler feedback as the
underrated comprehension channel. The psyche ruled MCP not very
relevant (JSON-forcing, not agent friendly; "the standard is still
cli's").

toolbelt — ast-grep (inherent impls, free functions, derive users),

cargo tree, clippy JSON — and the blocked declarations layer:
rustdoc JSON needs a nightly absent from the nix setup,
cargo-public-api hard-requires rustup, nixpkgs has no SCIP reader.

authored shape / expanded declarations / usage; grep is
structurally blind to the last two. Evidence landed in the
RustCodeAnalysisTools report.
