Design-skills prior art delivered (1): eight rules recur across
independent traditions without cross-citation (weighted by origin):
no shared mutable state; consumer-controlled bounded queues; message
passing as the only inter-entity communication; single-threaded
execution per entity; DAG topology preferred, cycles managed;
signals never go backward / terminal states irreversible; never
block the execution context; effects as data interpreted by the
runtime. Best skill-form sources: scala-best-practices §5 (already
SHOULD/MUST form), Armstrong's axioms, Akka Typed style guide
(decision checklists), Reactive Streams (numbered MUST rules + TCK).
No published AI-agent skill teaches actor/dataflow design — gap
confirmed by search, not hypothesized. Tensions with the three-part
machine: (a) actors are persistent things on the map, yet doctrine
says steps are walks — subflow's unreviewed hypothesis: the actor's
state is the coherent type, the handler is the conversion; (b)
dataflow tradition leaves intermediate types implicit vs types-first;
(c) the conversion spine is synchronous, actor responses cross
message boundaries. Deepest mesh: Elm Architecture = the three-part
machine made explicit; sans-io "I/O at the edges" = the pre-output
type renamed; event sourcing = a three-part machine across time.

Boundaries delivered (2, commit c922282f): the field converges on
what earns actor-hood — own serialized mutable state (Isolated Turn
Principle), own lifecycle, own failure domain (Armstrong's stated
primary motivation), true world concurrency (Armstrong 1:1 mapping,
"the program will quickly degenerate" otherwise), own pacing, and
distribution; no surveyed source assembles all six as one checklist.
Strongest anti-pattern origin is the Elixir language docs: "A
GenServer must never be used for code organization purposes."
Disconfirming side: WhatsApp 2M processes/server, Orleans trillions
of grains — fine granularity works where the RUNTIME owns lifecycle
and placement. Against the three-part machine: conversion arrows are
the clearest non-case; legitimate actor positions are shared-state
stores, boundary owners (ingress/storage), and paced sessions;
sans-io — the machine logic is a pure state machine inside the
actor, the actor is the shell at the I/O boundary.
