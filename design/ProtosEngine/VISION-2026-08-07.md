## The Protos Family

[ruled] **Four foundational languages.** **Ethos** — types and code, the
visualization-and-thought surface for code. **Dotos** — data, the same
surface for data (renamed from NOTA; the rename lands with the engine
train). **Nomos** — transformation rules. **Logos** — explicit program
representation, the assembly.
*source: dotosRename, 07-31; traitStandard, 08-01*

[ruled] **Conciseness gradient.** Ethos maximally concise; Nomos concise
where it can be (it carries emission structure); Logos fully explicit,
optimized as data representation, never for brevity.
*source: traitStandard, 08-01*

[ruled] **The non-repetition law.** Authored Ethos never repeats a symbol
the position or the governing Nomos object can imply; a repetition in
authored Ethos is an implementation failure. Corollary: a body needing a
parameter twice or in non-tail position is a different pattern — a
different Nomos object with its own most-terse surface.
*source: ethosNonRepetitionLaw, 08-01*

[ruled] **Division of labor.** Ethos specifies types (the anatomy); Dotos
fills them with data (the instances). Help for a Dotos-speaking object
emits the Ethos declaration of its types.
*source: ethosDotosDivisionAndHelp, 08-02*

[ruled] **Sugar doctrine.** Today's language surface is mostly sugar:
`main` is a trait on the main execution thread; generics and attributes
are Nomos objects. Per-need method: find the pattern, create the Nomos
transformer that gives the most elegant syntax — one that "only lets us
write the bits that change."
*source: threeLayerNaming, 08-01*

[ruled] **Delimiter rulings bind the whole family.** Dotos, Ethos, Nomos,
and Logos textual surfaces alike; no dialect keeps a superseded form.
*source: llmTokenOptimizationRulings, 08-04*

[ruled] **CLI arguments are Dotos objects.** Every CLI argument across
components; no Unix-style flags.
*source: traitStandard, 08-01*

## Three-Layer Naming and True Names

[ruled] **Three layers of identity.** **TrueName** — the content address,
derived from the object's body, changing on every edit. **EncodedName** —
the stable identity, randomly minted when a concept is introduced; the
encoded form references objects through it. **TextualName** — the
human-visible name, changeable freely without touching the encoded name.
Design speech must use the precise layer term, never the bare word
"name."
*source: threeLayerNaming, 08-01; traitVocabularyRulings, 08-07*

[ruled] **The association table `{EncodedName TrueName}` is the living
state,** updated by atomic operations; the change log records every
association so identities replay by reading, never by re-derivation.
*source: visionReacquisitionRulings, 08-05*

[ruled] **Same true name, same thing.** Byte-identical content is one
thing; there is no two-encoded-names-one-true-name dedup model. Repeated
byte-identical authored Nomos content must reuse the existing identity
rather than minting a new occurrence.
*source: atomicOperationEditing, 08-01; reuseEqualsCorrectness, 07-30*

[ruled] **Rebirth mints fresh; deletion is a real death.** A deleted
object recreated identically is a new object. True-name (Merkle)
recursion is reserved for frozen closures — pins and releases — where the
DAG law bars cycles.
*source: visionReacquisitionRulings, 08-05*

[ruled] **Trait `TrueNamed`, method `true_name()`, value `TrueName`.**
The identity capability trait follows the state-adjective pattern (like
`Ordered`). Chain: `EncodedForm: TrueNamed`; `TrueNamed` requires the
wire capability, its default `true_name()` hashes the rkyv wire bytes.
"Fingerprint" is dead as a synonym; "encodedid" does not enter the
vocabulary.
*source: traitVocabularyRulings, 08-07*

[ruled] **The true-name body is the rkyv payload of the strict typed
Ethos value.** Every kind of Ethos object has its own strict type; the
canonical body is the rkyv payload of that filled, validated value.
Identity is fixed at validation, before lowering, inside the authority
boundary. The hashed body excludes its own TextualName and carries
references as the referents' EncodedNames.
*source: redesignAuditRulings, 08-06*

[ruled] **Textual-form metadata is one record per object,** keyed to the
encoded identity, carrying the TextualName and module/file placement;
renames resolve through it to exactly one encoded identity. Imports are
textual-form-only; the encoded form addresses absolutely through
EncodedNames, and import sections are derived views. Hashes stay out of
textual projections.
*source: visionReacquisitionRulings, 08-05; ethosFileStructureCleanCut, 08-02*

[ruled] **No aliases anywhere.** No import alias, namespace alias, or
rename-on-import; every declaration is known by its own name only.
*source: schema-language ARCHITECTURE (psyche decision), 07-27*

[ruled] **The name table dies into the textual-form metadata store.** The
name-table component's claim that editing authored text allocates a fresh
EncodedName is disavowed — never a psyche ruling; EncodedName stability
across edits stands absolutely. The replacing store (name not yet chosen)
holds all textual-form metadata per object: the TextualName, and the
re-emission placement — the module or recursive submodule chain that lets
code re-emit into files without textual-name conflicts. The encoded form
itself carries no module concept (lean; one boundary to check: any
semantics that depend on grouping, such as a capsule's exported surface,
would need an encoded home).
*source: textualFormMetadataStore, 08-07*

## Syntax

| Surface | Ruling |
|:--|:--|
| `{ }` | Struct delimiter. *dotosSyntaxCorrections, 08-02* |
| `[ ]` | Enum body. *universalNamePrefix, 08-03* |
| `" ”` | String carrier (curly quotes), replacing all prior text forms. Common-indentation semantics; escapes: balanced nested pairs, `\"` `\"` for unbalanced literals, `\\` for backslash. *llmTokenOptimizationRulings, 08-04* |
| `(\| \|)` `[\| \|]` `{\| \|}` | [dead] All piped delimiters left the grammar. *llmTokenOptimizationRulings, 08-04* |
| `Name.{` | The application dot-prefix stands; the operator never separates from its delimiter. Token-free. *llmTokenOptimizationRulings, 08-04* |
| `< >` | Exclusive to **shapes** — engine-provided structural constructors (Vector, Option, ...), never authored. *visionReacquisitionRulings, 08-05* |
| `« »` | **Trait pickups**, guillemet-marked at every position including inside shape slots: `Vector<«Sortable»>`, `Range.{«Ordered» «Ordered»}`. One pair may carry several traits (the slot requires all). Unmarked names in shape slots are ordinary type references. *visionReacquisitionRulings, 08-05* |
| `Name:Transformer.(payload)` | The transformer application form. The colon binds declared name to transformer head; `.(` opens the payload. The sectioned form, the head-joining dot, the bare pipe, and multi-segment dotted chains are all dead. *redesignAuditRulings, 08-06* |
| `:` | Context-scoped: qualification in import space, name-to-transformer binding at declarations, ordinary character inside strings. *visionReacquisition, 08-05; redesignAudit, 08-06* |
| `interface.[A B C]` | Import entries carry their names in a square-bracket vector; the source-to-payload dot stands for now. *visionReacquisitionRulings, 08-05* |
| `Tick.7` `Range.{3 9}` | A single-field variant takes its payload block directly; the brace wrapper appears only for multi-field products. *dotosSyntaxCorrections, 08-02* |
| `method.{Params... Return}` | Signature convention: return type last, receiver implied by trait membership, borrowing and dispatch owned by the Nomos object. *ethosFileStructureCleanCut, 08-02* |

[ruled] **Syntax is grounded in parsing.** Every proposed form must state
how the reader classifies it at its position, what resolves, what binds,
and how the encoded form re-emits it: "always consider how it's going to
be encoded and decoded." Parsing is a context machine — every symbol's
meaning is scoped by the active typed parsing context; content is never
classified by scanning.
*source: streamNomosApplication, 08-02; visionReacquisition, 08-05; dotos ARCHITECTURE*

[ruled] **Operator written-once law.** An operator is written exactly once
(head of a standalone application) or zero times (its section supplies
it) — never as the second symbol of a name-first form.
*source: streamNomosApplication, 08-02*

[ruled] **Bare same-trait mentions co-refer.** Within one declaration,
repeated bare mentions of a trait denote one parameter,
instantiation-locked to one concrete type; distinct parameters sharing a
trait use the named form (`Left.Sortable`, `Right.Sortable`).
*source: llmTokenOptimizationRulings, 08-04*

[ruled] **Multiple textual projections are a standing given.** A
token-lean canonical projection for agents; a pretty-printed projection
for humans. Round-trip correctness is encoded-value equivalence, not byte
identity — with the carve-out that value-internal text stays meaningful.
Positional no-field-name records are the token-budget winner (-56% vs.
compact JSON).
*source: llmTokenOptimization, 08-04; encodedMeaningRoundTrip, 08-02*

[ruled] **CorrectNaming at the Rust boundary.** The concept layer uses
correct, legible names (`Ordered`, not `Ord`); Rust's abbreviations are
incorrectNaming, confined to Logos' Rust emission through a
`correctNaming / incorrectNaming` table that translates only shortened
code.
*source: llmTokenOptimizationRulings, 08-04*

### The Dotos Data Layer

[ruled] **Quotation safety.** Dotos never emits a double quote, so any
Dotos expression embeds escape-free inside every double-quote host (JSON,
Rust, Nix, YAML, shell, ...). Dotos plus schema form a pure data
specification — more specific than Rust. Comments are `;;`; the `@`
binding sigil is retired; the composite constructor is `KeyValue.(Key
Value)`, not Map.
*source: dotos ARCHITECTURE, 08-06*

[ruled] **No pipes anywhere.** The dotos architecture document's claim
that pipe-text survives for quotation safety is stale; the curly-quote
ruling governs family-wide with no Dotos exception.
*source: textualFormMetadataStore, 08-07*

## Traits

[ruled] **Traits are the code ontology.** Target: one hundred percent of
implementations under a trait; every method falls under a trait. Trait
proliferation is not a cost in the agent era. The 100% target is a soft
requirement — encouraged, never blocking — with unclear cases recorded in
a per-repo trait-migration file for psyche review, and every taken
exception noted at its site so drift in discretion is auditable.
*source: llmTokenOptimization, 08-04; traitStandard, 08-01*

[ruled] **Traits are always the first pass.** Contracts are written
before bodies. When neither an existing trait nor a clear new placement
can be found, stop and escalate to the psyche.
*source: traitStandard, 08-01*

[ruled] **Defaults whenever expressible.** A trait method carries a
default implementation whenever it can be expressed through the methods of
its required sub-traits; designing rich requirement chains to enable
defaults is one reason for traits-everywhere.
*source: traitVocabularyRulings, 08-07*

[ruled] **Generic parameters ARE traits.** There is no type variable in
the concept layer; Rust's `T` is a generated visible name in the assembly
projection. A parameter's identity is the referenced trait's encoded name
plus position. Multiple traits on one parameter are a contract list;
monomorphization vs. dynamic dispatch is an emission choice. There is no
unbounded generic form in Ethos — every parameter is trait-bounded.
*source: genericParametersAreTraits, 08-01; standards/vocabulary, 08-05*

[ruled] **Rust tuples are forbidden** in engine Rust — ad-hoc tuples and
multi-field tuple structs alike; the newtype (one-field wrapper) is
exempt and not considered a tuple. The positional-fields law governs the
Protos data model, not Rust source style.
*source: rustTuplesForbiddenLawScope, 07-30*

## Files, Capsules, Modules

[ruled] **Every Ethos file is header, imports, body.** The header carries
the ethos type and a SemVer-style version; imports are universal and
textual-form-only; the body is file-kind-specific. In a specialized file
kind, declarations carry no kind tag — the file type supplies it.
*source: ethosFileStructureCleanCut, 08-02*

[ruled] **File kinds differ only in their root type.** One shared
expected-type-at-position parsing machinery; per-file-kind parsing code
means the implementation failed.
*source: sameFormAndFileKinds, 08-01*

[provisional] **Seated file kinds.** Interface (Input / Output / Refusal
/ Declarations, Nomos admitted), Nexus (Traits / Declarations, Nomos
refused), Sema (PersistentDeclarations / Tables), plus
database-specification and likely a design/traits kind. Schemas are
provisionally accepted for MVP; psyche review is deferred, not waived —
tracked as bead `primary-5pm`.
*source: ethosFileStructureCleanCut, 08-02; core-ethos ARCHITECTURE, 08-07; deepCenterVision, 08-06*

[ruled] **A capsule is a program or library** — the unit whose content
yields one compiled artifact. Rendering a capsule to text is a balanced
distribution into reasonably sized files: files in are not files out;
file granularity carries no identity.
*source: capsuleIsCompilationUnit, 08-01*

[ruled] **The root container is just a module** — no coined term;
everything beneath is submodules, recursing uniformly. Ethos sources live
in the owning component's repository.
*source: deepCenterVision, 08-06; visionReacquisition, 08-05*

[ruled] **Text files are bootstrap.** Eventually the engine holds the
source in encoded form and a user pulls a textual representation from the
engine.
*source: threeLayerNaming, 08-01*

## Engine and Operations

[ruled] **Atomic operational editing.** Every change enters as one
operation through the operation interface (a signal message), applying in
full or not at all. Engines hold the encoded form in slots; the
per-engine change log of operations is the version control system. A
generated object's slot is created by the operation that first produces
it and edited by operations changing its sources — continuity is
structural, not inferred. Machinery is named in plain English (operation,
slot, change log); exotic naming is reserved for the language family.
*source: atomicOperationEditing, 08-01*

[ruled] **The dependency DAG law.** Transformation and derivation
dependencies form a DAG; cycles refuse with a typed error naming the
loop, and the refusing operation changes nothing. Cascaded regeneration
walks topologically. No lazy evaluation, no fixpoint evaluator, no
constraint-region machinery — permanently out.
*source: dependencyDagLaw, 08-01*

[ruled] **Strict purpose-designed encoded types.** Every encoded form is
carried by types designed for that exact form; generic container shapes
are barred from encoded surfaces. One strict application type per
transformer — no generic transformer-application node; per-transformer
types live in a shared `nomos-types` crate. Ethos mirrors the input
schemas of Nomos transformers; the general law: each daemon holds the
types storing the next daemon's objects.
*source: llmTokenOptimizationRulings, 08-04*

[ruled] **Sema is the shared database engine,** not a chain daemon. The
versioned operation log is the single source of truth; the redb store is
a rebuildable materialized view folded from the log. The horizon: full
distributed-VCS semantics over the typed database — branching, forking,
rebasing, merging, with per-component merge policy — and
Sema-on-Sema, computation itself content-addressable. Archival lowering
precedes hard deletion.
*source: llmTokenOpt, 08-04; sema ARCHITECTURE*

[ruled] **One cryptographic basis:** blake3 for all content addressing,
Criome BLS (BLS12-381) for signing and attesting history; no component
diverges.
*source: sema ARCHITECTURE*

[ruled] **Daemons are Dotos-free.** rkyv binary is the single encoded
form for database and wire; Dotos text is the projection at the
CLI/inspection edge, gated behind a feature. Signal carries binary only.
Bootstrap and runtime configuration are one vocabulary: a daemon takes
one pre-generated rkyv Configure message, and the same type is accepted
live for reconfiguration. Component feedback is typed enums/structs,
never message strings. Macros are serializable data objects — name,
position, pattern, template as data trees — interpreted by one small
generic interpreter.
*source: dotos / signal ARCHITECTURE, 08-06*

[ruled] **The bootstrap commit is atomic.** One commit journals the
authorized identity/metadata transition and installs canonical Ethos
source and generated Rust together; callers cannot manufacture authority
proofs, receipts, seats, or fixture vocabularies. The nomos-engine
boundary is authority-sealed: it cannot accept a draft, substitute a
reader, allocate an identity, or reconstruct another Ethos representation.
*source: redesignAuditRulings, 08-06; nomos-engine ARCHITECTURE, 08-07*

[ruled] **The database evolution engine.** The diff of two Ethos-encoded
schema versions produces the migration logic — a native operational route
and a textual bootstrap route (LLM-aided if ambiguous) — compiled either
into the next program version or a standalone migration executable.
Encoded-name persistence makes renames migration-free by construction.
*source: databaseEvolutionEngine, 08-02*

[ruled] **Foreign interfaces belong in Logos,** exposed through a
specialized Nomos object.
*source: threeLayerNaming, 08-01*

[ruled] **Visibility's only surviving purpose is invariant protection.**
Shadowing is structurally impossible in the encoded form (references are
absolute EncodedNames; no name-resolution step exists). Visibility does
not exist in Protos as a feature. What survives is authority over
mutation, not access to names. Guarded objects (guardian-set concept) are
a deferred idea, not ruled into the design.
*source: visibilityAndGuardedObjects, 08-07*

## Interfaces and Components

[ruled] **Sections confer the universal traits.** Placement in an
Interface section makes each item implement its section's trait — Input,
Output, Refusal — living in the `protos` crate. (Briefly superseded, then
reversed the same day: "never written" is disavowed; placement *is* the
writing of membership.)
*source: redesignAuditRulings, 08-06*

[ruled] **Stream is a fourth role kind.** The Interface body gains a
Stream section; placement confers the stream's universal trait. No source
object bundles a stream's components — opening query, stream, and
termination are separately authored objects; the shipped bundled family
expansion is disqualified and must be deleted. Bootstrap scope: initiation
and termination are hand-authored input objects ([provisional]
StreamInitiation / StreamTermination naming), wired by hand.
Synthetic-naming transformers (Observer to ObserverStreamInitiation...) are
envisioned but explicitly deferred.
*source: redesignAuditRulings, 08-06*

[ruled] **Signal is message triage only.** Admission, dispatch,
identity-stamping, validation, wire framing — nothing more; the target is
one universal mail mechanism every component speaks, with framing and
routes declared in schema. A 64-bit per-message short header (root verb +
seven sub-enums) discriminates any namespace object in constant time,
symmetric between wire and engine. Sema's classification vocabulary stays
internal; sink delivery is downstream of commit and cannot roll back a
mutation.
*source: signal / sema-engine ARCHITECTURE*

[ruled] **The nexus schema is the feature catalog.** Every internal
feature is declared as a Nexus verb/object in the component schema, never
as inline hidden logic. The only file a daemon may use for its data is
its sema database. Single-word values are heading toward
spelling-constrained dynamic enums stored as integers (direction, not
cutover).
*source: triad-runtime / standards*

[ruled] **protos-engine is a dependency sink, not a code repository** —
no Cargo package or Rust implementation; all inputs resolve from full
published Git revisions, pins advancing only after independently accepted
publication. The ethos-engine target is a stateful Ethos daemon with an
embedded sema database plus a small translator daemon owning shared
naming and encoded-identity allocation; the current central-storage
socket path is explicitly not the target.
*source: protos-engine, 08-05; ethos-engine ARCHITECTURE*
