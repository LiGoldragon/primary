# Ethos in the runtime: Flow, rerun at 0.56.2

Rerun of the Flow section of `/home/li/primary/flows/00e2a8/audits/ethos-in-runtime.txt`, using the same method and questions. The audit read Flow 0.54.7 (c8f526ce). This rerun reads Flow 0.56.2 (eabddc8d), live. Audited 2026-11-14, read-only: nothing was built, restarted, messaged or committed. The one write was a `git fetch` in the local signal-flow and meta-signal-flow clones, which moved only their remote-tracking refs.

## Verdict

Before, Flow was **partly** on Ethos: the wire and Operation were, and Memory mostly was not. Now Flow is **mostly yes**.

| root | written in ethos | generated by ethos-zero, checked by build.rs | used on live paths | hand types still doing the same job |
|---|---|---|---|---|
| Signal (signal-flow, meta-signal-flow, signal-curriculum-nexus) | yes | yes | **yes**: dispatch now goes through the generated `Answerable` | 4 same-name shadows; 3 hand dispatch front-ends |
| Operation | yes | yes | **yes** | none found |
| Memory | yes | yes | **yes for record shapes** | 0 current-schema records. 51 frozen predecessor shapes. Each record's key, table, version and schema hash is still hand-written |
| Emission | yes | yes | **partly**: 5 call families are typed, 3 are still hand-built | Codex app-server, Herdr `events.subscribe`, the Claude settings document |
| Library (flow-ethos; flow-nexus library, startup, starter, send_tool, landing; flow and flow-meta invocation) | yes | yes | **yes**, except landing | landing.ethos is generated and checked but never compiled |

## Signal: yes

- **Written and checked.** signal-flow `ethos/signal.ethos` (1054 lines), meta-signal-flow `ethos/signal.ethos` (663 lines) and signal-curriculum-nexus `ethos/signal.ethos`. Each is a Signal root, has a build.rs freshness assert, and a lib.rs that is only `pub use generated::signal::*` plus re-exports. The wire identity is still the digest of the ethos text (`CONTRACT_SOURCE = ETHOS`, signal-flow lib.rs:23).
- **Live use, ordinary socket:**
  - `Connection::serve_ordinary` (lib.rs:1999) calls `dispatch_serially` at lib.rs:2209 and nearby.
  - That calls `dispatch_from` (lib.rs:336), which calls `query.answer(&OrdinaryCall { .. })`.
  - `answer` is the generated `impl Answerable for Input` (signal-flow generated/signal.rs:2150). It calls `impl signal_flow::Answering for OrdinaryCall` (lib.rs:465).
  - Before, this was a hand `match query` in `dispatch_from` (old lib.rs:338).
- **Live use, meta socket:** `serve_meta` (lib.rs:2228) calls `dispatch_meta_serially` (lib.rs:2242), then `dispatch_meta_from` (lib.rs:448), then the generated `meta_signal_flow::Answerable` (generated/signal.rs:1448), then `impl Answering for MetaCall` (lib.rs:1087).
- **Live use, Curriculum:** `CurriculumQuery` and `CurriculumOutcome` now come from signal-curriculum-nexus (lib.rs:20, context.rs:34). The second copy the audit found was removed in a50f0f61.
- **Still hand-written beside it:**
  - **Dispatch front-ends.** `serve_ordinary` and `serve_meta` handle by hand the inputs that need the connection: streams, the peer process, effects after the answer is written. `dispatch_metaflow_peer` (metaflow.rs:80) answers a `MetaflowAnswer`, which carries more than an Output. Every other input falls through to the generated dispatch.
  - **Same-name shadows of ethos types**, 4 left of the audit's 6:
    - `SeatEvidence`, sending.rs:691: `u64` and `Option<String>`, against signal.ethos:849.
    - `NativeTargetRefusal`, herdr/launch.rs:201.
    - `RegistrationRefusal`, herdr/launch.rs:222. It is converted to the wire type at launch.rs:4367.
    - `CodexEndpoint`, codex.rs:72: `PathBuf`, `BTreeSet`, plus socket and transcript_root, against library.ethos:100.
  - **Resolved since the audit:**
    - `FlowLifecycle`'s hand twin is gone.
    - `NativeTranscriptCursor`'s hand twin is gone. The name clash has moved into Ethos itself: memory.ethos:212 declares `{ Device Inode Offset }`, and signal.ethos:572 declares a six-field type with the same name.
