## Method and limits
`/tmp/flow-d42f0a-loss/{reader.rs,default.nix,compare.py}` are the complete probe. Build4 compiled only an extra binary against the exact published Flow 52e library via build-base overrideBinaries. The relevant generated Memory and production store/upgrade definitions are unchanged from accepted R0 37980. It uses **redb ReadOnlyDatabase + ReadTransaction only**, not Engine/FlowStore open, a daemon, upgrade or repair. Kernel schema 3, engine layout 7, catalog family hashes and checked rkyv record decoding all passed for both immutable disposable copies. Known catalogued-but-physically-absent lazy tables are empty by the kernel's documented read semantics; unknown schemas/types refuse.
Builder duplicate hashes before and after are identical and match original capture receipts: pre cc36ec51889d5a17efaf60681bc89aa2a27433a78100aae5ee4354c879ec5805; upgraded cbf9fedea5a41069fda9bd50626fd7323ff2254f3a1b7648784e77010bccf8c9. Originals were never opened by the probe. Raw dumps are `pre.json` and `upgraded.json`; complete delta/summary files are beside them.
**This is the exact loss/reversion set at restoration, not a claim about the current live ledger.** Post-rollback requests, subsequent answers and possible request-ID reuse were not read by this offline probe. Per-delivery admission times are absent; the 94 new records are bounded by the two same-day capture times. No replay or Memory mutation was performed. Failed reader iterations are retained: compile-time missing MemoryDefinition impls were replaced by exact owner schema labels; a raw-counter type mismatch and lazy absent-table refusal were corrected against pinned kernel semantics before either complete result was accepted.
