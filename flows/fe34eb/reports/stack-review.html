2 What was ruled and landed on 2026-09-10

Landed in the distilled Vision, commit 6c4e16f:

  • Nexus is the word for the style of component that speaks signal and uses a similar database. Every component built from now on is a Nexus. The nexus repository is the library that defines the core of a Nexus component.
  • The "daemon lives in Ethos Zero" sentence and the nexus-core heading are gone. Ethos has three roots: Library, Signal, Sema. Signal gives a Nexus its main types and Sema its database types.
  • Ethos Zero was first named Ethos Monolith; the two are the same thing. Zero as in version 0: no daemon yet, no Nexus. The ethos repository is for the ethos nexus that follows. There is no ethos-monolith repository; GitHub redirects the name to ethos-zero.
  • Signal is portable rkyv (a binary serialization format) plus whatever protocol is standardized on top of it; the protocol is still to be decided. The sentence naming CapnProto (an earlier candidate serialization format) is gone.
  • The router's enum is held in the signal repository, which every component depends on.
  • The undelimited string form is named bare: a bare string, undelimited because it needs no delimiters.
  • Raw records that spoke of a nexus core or a Nexus execution engine were archived as superseded, none deleted.

3 The signal area

Findings

  • The realized nexuses use none of the four signal repositories.
  • The wire today says nothing about itself: no envelope, no contract identity, no revision, no handshake. The Rust type is the only discriminator, and only at compile time.
  • signal-frame has the design the wire lacks, but sits on the legacy dotos stack and its macro emits dotos codecs.
  • signal-standard is on the realized stack's side and names Lojix and Orchestrate in its roster, but nothing live uses it and most of its tree is dead.
  • The legacy signal repository holds one thing worth carrying forward: four sections of its architecture document — origin route as implicit return address; authorization at the wire through two sockets rather than a permission variant; reply by position without correlation ids; one record, one form. Its code is superseded; its history is not needed beyond that document.
  • The duplication to resolve is the six identical copies of the Signal type in the contracts, and the three copies of the length prefix in the nexuses. That is the code written most recently.

4 Proposal for the signal repository

  1. Rename signal-standard to signal, discarding its orphaned files and keeping its ethos files and generated taxonomy. Archive the legacy signal repository, carrying only the four architecture sections into the new one as a design document.
  2. Move the 72 lines the six contracts share into signal, so every generated contract depends on signal and carries none of it itself; ethos-zero emits contracts against signal's kinds.
  3. Move the length-prefix framing into signal, so Lojix and Orchestrate depend on it once instead of three times.
  4. The protocol — everything signal-frame designed and the wire now lacks — stays to be decided, and is designed in signal when taken up. signal-frame is left as it is, a reference.
  5. signal-derive is archived with the legacy signal; its only dependent was that repository.

Open question for the living: does signal-standard's taxonomy belong in signal at all? Nothing realized needs a component roster yet; the router that would is not built. If not, signal is born with only the shared Signal type and the framing.
