## Flow-held state: two different notions

Inspect exposes **MetaflowState** (Awake as FlowId / Asleep), not **State** (Acting / Resting / Crystallizing / Asleep). Internal `HeedsOverrides.state_now` first requires live lifecycle plus exact Awake FlowId; otherwise Asleep; for a live Awake seat it uses last transition, defaulting Acting on absent/error (`src/overriding.rs:55–77`). `FlowStore.state_of` reads the last durable transition (`src/store/transitions.rs:168–183`).

There is no corresponding query in either inspected contract. Meta `ReadEvents.<flow-id>` returns ordered HarnessEventMetadata, not transitions; Debug returns address and IDs (`meta ethos:395,453–459,745`). Codex ledger transitions and SetState overrides therefore cannot be reconstructed from ReadEvents. Inspect/Current/Metaflows cannot certify the internal state the quiet-window comparison requests. Hold and Resume record current internal state but answer no state snapshot.

## Hook diagnostics and counts

Hook implementation is `../flow/src/hook.rs:450–507`. It emits exactly one stderr diagnostic and no stdout. Fields are tab-separated **event name, compact metadata datom, CLI-equivalent code, reply/error**. Metadata carries FlowId, optional process birth and event metadata; Stop metadata holds session, transcript path and background work, omitting assistant message text. Normal transport gives code0 on successful call or2 on error. Code0 does not by itself mean Reported: inspect the reply for typed refusal. Missing configuration uses `-`; ignored/no-FLOW_ID events use `-`; malformed Stop uses typed refusal and actual process exit1, with no Report. Ordinary hook transport error still ends with process exit0. Thus process exit counts are not refused-Report counts.

This code selects **stderr, not a durable sink**. No verified existing file/journal capture path or retention/count boundary is provided by this source. Daemon journal digest-refusal diagnostics cover a different boundary and cannot count hook invocations lost before the daemon. During the mixed-contract window exact source digests refuse old clients before Input; a captured hook line may prove a failed attempt, not a replay. Counts require Field to identify and witness actual stderr capture for every participating harness process, interval start/end and gaps. Until then report **count unknown**, never zero. A new wrapper/capture mechanism would need its own ruled scope and actual evidence; none was installed here.
