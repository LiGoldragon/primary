Presentation.{ «Rust toolchain» }

## Measured 8 October

154 repositories hold Rust; 145 are built by Nix. 97 build on nightly, 47 on stable, one on the nixpkgs compiler.

The nightly is mostly the one of 18 June (1.98.0-nightly, 88 repositories). Today's stable, 1.99.0, is newer than it. Today: stable 1.99.0, beta 1.100.0, nightly 1.101.0 of 7 October.

No repository uses a nightly feature. All are on edition 2024 except whisrs (2021); 2024 is the newest edition, and nightly has none after it.

rust-build already gives nightly to every repository that builds through it. 67 `rust-toolchain.toml` files say stable or a fixed version while Nix builds nightly. 37 repositories call fenix stable directly, 24 call fenix nightly directly, each with its own lock.

## Proposal 1: `mind-skills/skills/operation-nix-workflow.md`, the policy

Added, after the line on Rust runtimes:

Rust builds on one cluster toolchain: nightly, the fenix `complete` set, through `rust-build`. Its only pin is rust-build's fenix lock. The pin advances on each stable release day, every six weeks, once rust-build's checks pass, and the Rust repositories then take the new rust-build lock. A repository calls no fenix toolchain of its own and keeps no `rust-toolchain.toml`. A nightly feature marked incomplete is not used.

## Proposal 2: `mind-skills/skills/knowledge-rust-toolchain.md`, new

Added, the whole skill:

The cluster compiler today is `rustc 1.101.0-nightly (1d81eb4ad 2026-10-07)`, fenix `complete`, pinned in `rust-build`'s lock at fenix `0a07e335`. To advance it: `nix flake update fenix` in rust-build, run its checks, push, then `nix flake update rust-build` in each Rust repository. The next advance is 12 November 2026, when 1.100 becomes stable.

Features open on nightly, closed on stable 1.99, and what each could serve here:

- `never_type`: `Result<T, !>` for codecs that cannot fail; stable from 1.100.
- `try_blocks`: error paths inside protos parsers.
- `gen_blocks`: protos printers and parsers written as generators.
- `min_specialization`: one blanket datom impl, with the intrinsics overriding it.
- `adt_const_params`: datom kinds as enum const parameters.
- `default_field_values`: field defaults in Rust generated by ethos-zero.
- `trait_alias` and `associated_type_defaults`: named trait bundles for trait-first crates.
- `impl_trait_in_assoc_type` and `return_type_notation`: `Send` bounds and returned futures in actor traits.
- `const_trait_impl`: traits callable in `const`; written `const impl`.

Marked incomplete, not used: `generic_const_exprs`, `inherent_associated_types`, `ergonomic_clones`, `pin_ergonomics`, `async_drop`.

Nightly changes under its users: between June and October `box_patterns` and `associated_const_equality` were removed, and `impl const` became `const impl`. A crate using a feature names it in its ARCHITECTURE.md, so an advance that breaks it is found by name.

## Proposal 5: the 82 repositories that build through rust-build

Each `flake.lock` takes the new rust-build; each `flake.nix` that passes a toolchain file calls `fromPkgs`; each `rust-toolchain.toml` is deleted.

Removed: the `fromToolchainFile pkgs { file; sha256; }` call, and `rust-toolchain.toml`.

```nix
+rust = rust-build.lib.${system}.fromPkgs pkgs;
```

Nine of them still lock a rust-build from before nightly and build on 1.85.0, 1.88.0 or a hash-frozen stable: dotos, nota, schema, schema-language, schema-rust, signal-spirit, meta-signal-spirit, clavifaber, cloud.

## Proposal 6: the 62 repositories that call fenix directly

37 on stable (1.95 to 1.99), 24 on nightly (three dates), meta-signal-message on 1.89.0. Each `flake.nix` builds through rust-build instead; `rust-toolchain.toml` is deleted.

```nix
-fenix.url = "github:nix-community/fenix";
+rust-build.url = "github:LiGoldragon/rust-build";
```

Removed: the `fenix.packages.${system}.<channel>.withComponents [ … ]` toolchain and the crane override built on it.

```nix
+rust = rust-build.lib.${system}.fromPkgs pkgs;
+craneLib = rust.craneLib;
+toolchain = rust.toolchain;
```
