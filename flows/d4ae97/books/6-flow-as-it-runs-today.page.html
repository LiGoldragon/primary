Flow as it runs today

Four proposals for the skill that tells flows how Flow works today. The skill lives in mind-skills, file skills/knowledge-flow.md. Each adds lines at the end of the file; nothing is removed. Each asks one ruling: accept, change, or refuse.

The first, second and fourth rest on reading the Flow source code in the current checkout. The comment-wake lines rest on a retained report about the harness (the program that runs a model), which is a claim, not something seen running. No line rests on a check of the live service, so each added line says so.

1. What Flow stores and what reports do

Why: a flow that must find another flow needs to know what Flow keeps. A node is the stored record of one flow. A FlowId is the short name of a flow. The meta socket is the owner-only channel.

File: mind-skills/skills/knowledge-flow.md

Removed: none.

+Source reading, not a live check: Flow keeps a
+registry of nodes. A node holds the FlowId, the
+native session (the harness's own session
+name), the harness, the Herdr route (the
+terminal pane the flow runs in), the origin and
+the life stage. Flow can read one node or list
+them. A harness report names a FlowId and an
+event. Flow files the event under that flow,
+and the owner reads it on the meta socket. A
+report for an unknown FlowId is refused, never
+adopted as a new flow.

Ruling: accept, change, or refuse.

2. Reaching a flow, and watched comments

Why: sending a message is the commonest act. A lease is an exclusive claim on a pane. The input box is the line where text is typed. A watched artifact is a published page whose comments a flow is told about.

File: mind-skills/skills/knowledge-flow.md

Removed: none.

+Source reading, not a live check: delivery
+finds a stored live node. It refuses a flow
+that is stopped, retired or exited, refuses a
+held successor, and needs a Herdr route and a
+harness profile. Under its lease Flow types
+into the pane only if the route matches Herdr,
+the agent is not blocked and the input box is
+empty.
+Reported by a retained harness report, not
+seen: a subflow can publish a book that arms
+its parent main loop. On a watched artifact,
+"@Claude" or "Send to Claude" wakes that main
+loop; a plain comment does not notify it. The
+continuous main loop holds the watch, not a
+short-lived Book flow.

Ruling: accept, change, or refuse.

3. What does not wake a flow

Why: a flow may expect that a comment or message wakes a sleeping seat. The evidence stops short of that. A webhook is a call the product would make to a listener when something happens.

File: mind-skills/skills/knowledge-flow.md

Removed: none.

+Source reading, not a live check: delivery
+targets an existing pane. A missing pane is
+recorded as Exited and the write is refused.
+Blocked, unavailable and occupied routes are
+refused before typing.
+Reported, not seen: the harness contract
+separates "@Claude" or "Send to Claude" from a
+plain comment. No real Claude.ai wake of an
+idle session was seen. The report found no
+public comment webhook, no delivery to the
+owner's session and no automatic idle wake.
+That bounds the evidence; it does not prove a
+private route cannot exist.
+No source supports waking every flow or
+polling every seat. The route is targeted:
+comment source, a named continuous main loop,
+then a Flow or messenger event.

Ruling: accept, change, or refuse.

4. Refusals and limits of evidence

Why: a flow reading a refusal should know the failure is a named case. It should also know which facts stay separate.

File: mind-skills/skills/knowledge-flow.md

Removed: none.

+Source reading, not a live check: these end in
+an explicit refusal: unknown flow, stopped,
+retired, exited, unavailable, blocked,
+occupied, and a failure to save. A report that
+cannot be saved is refused as an unknown flow,
+never shown as delivered.
+The old record of a publisher-only watch is
+history, not a present guarantee. Generated
+tool schemas are not evidence of the live
+product. The harness watch contract is a claim
+about that path, not proof of a real idle wake.
+Keep these facts apart: the source checkout,
+the deployed binary, the service version, a
+socket answer, a Herdr listing, a native
+binding, a first turn, and a delivered comment.
+A missing record does not mean dead. A source
+line does not mean live.

Ruling: accept, change, or refuse.
