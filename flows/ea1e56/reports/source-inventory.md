# ChatGPT Desktop / persistent Codex source inventory

Inventory date: 2026-09-02. Source was read from the `CriomOS-home` checkout at `/git/github.com/LiGoldragon/CriomOS-home`; revision evidence uses `jj`. No product source or runtime state was changed.

## Bottom line

The current path is distributed across four layers:

- The Home package downloads the signed OpenAI ChatGPT Debian package, installs it, supplies a managed Codex executable at Electron's `resources/codex` candidate path, and wraps the launcher to select the native local-daemon branch while clearing CLI/private-pipe overrides.
- `owned-agents/chatgpt/patch-asar.py` modifies the vendor `app.asar`. Its current dirty version disables startup overrides, removes several private `codex_app` producers, and sanitizes thread requests. The source patch is the largest removal-relevant hack.
- `codex-remote-control.service` remains the declared persistent app-server owner. The TUI wrapper routes ordinary terminal sessions to its `unix://` endpoint and blocks unmanaged lifecycle/remote-control routes.
- Home/CriomOS select and deploy these pieces. The actual ChatGPT GUI connection is not expressed as a Home socket path: current source relies on the vendor local-daemon behavior and an injected CLI candidate. A successful GUI `thread/start` or `thread/resume` is not established by source inspection or the retained witnesses.

Removal-relevant current state:

- `main` is `90a12633cc60` (`Upgrade Codex and ChatGPT producer stack`), with ChatGPT `26.831.21537` and Codex `0.152.1` pinned. The working copy is dirty at `438d70ff5f60`: `patch-asar.py` and `checks/desktop-app-support/default.nix` contain additional uncommitted sanitizer/ASAR checks, and `owned-agents/chatgpt/__pycache__/patch-asar.cpython-314.pyc` is a generated artifact, not authored source.
- The old `codexDesktopGate` implementation and gate check were deleted in `64d4784969e8`; the current ChatGPT package symlinks the raw canonical Codex executable instead. Do not look for a current gate file when removing this path.
- Current Home sources contain no declarative `mcp_servers.codex_app` or `mcpServers.codex_app` entry. `codex_app` occurs only in the ASAR patch comments/patterns, test fixtures, the Codex parser smoke, and upgrade prose. `mcp_servers.agent-intercom` is a different, current MCP entry.
- Removing ChatGPT does not automatically imply removing `codex-remote-control`, the TUI wrapper, Agent Intercom, or the Codex package: those have independent terminal/phone/bridge consumers. Removing the owner is a separate authority decision.

## Evidence boundaries and unresolved questions

- Direct observations here are current source text, current `jj` status/history, and absence/presence checks from `rg`. They establish authored intent and revision state, not that the installed Electron process uses those bytes.
- The current `desktop-app-support` check is designed to exercise package wiring, environment neutralization, candidate version, ASAR marker presence, JavaScript parseability, and Codex's response to invalid versus clean test requests. The source inventory did not run that check, and it does not drive a real ChatGPT GUI new-chat or resumed-thread operation.
- Retained flow reports/witnesses record a prior ChatGPT `thread/start` failure (`invalid transport in mcp_servers.codex_app`), a later ASAR parse error from an extra closing brace, and a successful WebSocket `initialize`; they do not prove the normal Composer's final request producer or a successful GUI `thread/start`/`thread/resume`. Treat the `cj`/`h0` and Composer path as source-derived hypotheses until re-witnessed.
- The psyche's current typed statement is: “I am no longer interested in heavily modifying those applications to achieve better functionality.” It expresses direction, but does not settle whether to remove only ChatGPT customizations, the persistent Codex owner, Agent Intercom, full-access defaults, the independent sidebar, or all of them. That product/authority choice remains open.
