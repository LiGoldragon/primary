This is a non-executable positional template. The literal
`$HORIZON_DEFINITION` substitution is illustrative.

The Ouranos route was revalidated with strict BatchMode SSH and returned
`ouranos`. The bare-brace transport and selector syntax is source-backed:
the named `DeploymentTransport.{...}` form was rejected by the current parser.
`Some.@/etc/nix/machines` makes Lojix pass `--builders @/etc/nix/machines` and
`--option max-jobs 0`; that file names only Prometheus. Unlike the direct Nix
definition build, however, Lojix omits `--option fallback false`. Its systemd
environment has no `NIX_CONFIG`, while `env NIX_CONFIG='fallback = false' nix
config show` affects only the client process. This template is therefore
**blocked** and was not submitted: it could fall back to local compilation.
The disconnected preflight returned `proposal source is not a Horizon
definition` before socket exchange. That is a compatibility preflight result,
not proof that the built child is invalid: Horizon CLI parsing passed. `NoSecrets`
was not claimed to work; the candidate requires the encrypted secrets directory
for OpenCodeTesting.
