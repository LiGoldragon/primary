# Browser read command beside Playwright — reduced write-set proposal

Authority: Core1scy relays Psyche7v91/Fable3t5x, superseding the earlier architecture proposal. Proposal only, before implementation, schema bodies, registry/account reads or gates.

## Functional contract

One command beside playwright-chrome reads a Field-configured named page and named fields, returning only datom values or typed refusal, with no model. A partial read refuses naming missing fields and returns no partial values. It opens one temporary tab in running Chrome and closes that same tab after the attempt, including failures; it preserves the user's existing tabs/session. Plain wrapper driving stays available to Field for unknown pages; discoveries become registry entries. Version1 reads only.

The registry is runtime datom data under the user configuration directory set by Field. Page names, addresses, named fields, extraction definitions and operating limits are Field configuration, never code/Nix/account defaults. First eventual entry is Anthropic Console Billing rows, supplied by Field after approval; this proposal reads or authors no account data.

## Proposed datom shapes for ruling, not implemented schemas

Request: Read.{ PageName [ FieldName ... ] }. Registry: Registry.[ { PageName Address [ { FieldName Extraction } ... ] } ... ], with operating limits in runtime configuration; concrete extraction variants/value types require ruling. Reply: Values.[ { FieldName Value } ... ] or Refused.Reason; partial read uses Refused.MissingFields.[ FieldName ... ] without partial values. Unknown page/field, absent/invalid registry, unsupported session, navigation/extraction failure and cleanup failure need explicitly accepted typed reasons. No free-text question/model or arbitrary caller-supplied address/executable/evaluation code enters this request.

Open contract choices BEFORE BODIES: exact runtime configuration-directory/registry-file selection convention (Field-owned, no Home data/default registry), datom parser/printer capability, extraction grammar, duplicate/empty request handling, value types and deterministic ordering, operating limits, refusal/redaction/cleanup precedence, and supported existing session/attach/read mechanism.
