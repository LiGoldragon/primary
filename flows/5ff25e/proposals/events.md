::: comment

+ ## Every action answers an event

+ Polling, in any form and for any reason, is out of every design. Every action has a cause, and the cause is an event; a design names the event each action answers and finds where that event is announced, and the system is quiet when nothing has happened. A need whose event is not yet found is brought to Psyche, who finds it.

### Proposal 2: the operating system's line · psyche-belief › vision/criomos.md

::: comment
Added at the end of the module, as its own section.
:::

+ ## Between events the operating system is silent

+ CriomOS has no polling of any kind: no timer, no periodic job, no loop that looks. A service acts when something it listens to tells it: a path unit, a socket, a hook, a word from the kernel or from a Nexus. A writer who needs an event he cannot reach brings the need to Psyche, who finds the event; between events the operating system is silent.
