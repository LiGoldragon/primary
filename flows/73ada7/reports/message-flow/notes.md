## Pulls against the constraints

1. Message text is a string. "A better version of message should be redone and redeployed with just a string as the basic form." (F`b7ba00/vision/messaging.md`, 2026-09-26) and "the payload at the end being a string. That way we get a sort of strongly typed string" (F`b7ba00/vision/meaningLanguage.md`, 2026-09-26) put a string in `Body` and `Psyche`, against "It's going to be forbidden for string handling to be in the Nexus." (F`8475a9/vision/datom.md`, 2026-10-05). Written as `Meaning`, which still holds one opaque string.
2. `Meaning` brings datom-codec into the Nexus. knowledge-ethos: "where a position holds a `Decimal`, a `Meaning` or a datom-codec `Error`, it enables datom-codec 0.32.2's `rkyv` feature ... unconditionally", against "There should be no datom in any Nexus." (F`8475a9/vision/datom.md`, 2026-10-05).
3. Flow writes text into a terminal. "a request to send this text into a particular harness" and "Flow would even be the part that sends the text" (F`1b8ac0/vision/messaging.md`, 2026-09-21): Flow's `Write` must render the message as text inside the Flow Nexus.
4. The message lands as datom. "The message body is a datom that lands in the recipient's prompt as a datom-formatted object." (PS`vision-messaging.md`) needs datom produced by whoever writes the prompt, which is Flow; the living's own open question: "how does Nexus send datom to places without needing to know how to deserialize and serialize datom itself?" (F`5578cc/notion/nexus.md`, 2026-10-03).
5. Topic as a PascalCase string. "The topic is a string but it's a certain type of string. ... It's basically PascalCase of a certain number of words" (F`d4ae97/vision/flow.md`, 2026-10-08), against "these will even become variants" (F`edf227/vision/topics.md`, 2026-10-03). Written as variants; only `Core` and `Testing` are named.
6. Role as a camel-case string. "we describe a role as maybe some kind of short camelcase expression, a string" (F`f5a6e9/vision/flow.md`, 2026-10-07). Left out.
7. Flow id as an integer. "The Nexus just thinks of it as a hash, which is maybe an integer with certain kinds of traits" and "If 33 bits, for me, I think it is enough entropy" (F`edf227/vision/identifiers.md`, 2026-10-03). Ethos has no hash or byte intrinsic, so `FlowId.{ Hash }` imports `signal:Hash`; a search of `/git/github.com/LiGoldragon/signal` found no such type.
8. Sender in the message kind. "field report, psyche report, field question, psyche question" (F`b7ba00/vision/messaging.md`, 2026-09-26) names the sender's aspect inside the kind, which the caller identity already carries. Written as `Report` and `Question`.
9. Sender as voice only. "for now the sender is psyche primary or psyche secondary, etc." (F`b7ba00/vision/messaging.md`, 2026-09-26) has no topic, while a metaflow has one; and "not every message will come from a voice" (F`8475a9/vision/messenger.md`, 2026-10-05): a job flow has no `Sender` here.
10. Simple and full as two forms. "A simple message, a simple psyche" and "A full message that can have many fields" (F`b7ba00/vision/messaging.md`, 2026-09-26) and "defined in ethos somewhere in signal as different types of formats" (F`edf227/vision/signalForms.md`, 2026-10-03) pull toward two types for one datum, a double type; ethos-zero has no formats section. Written as one `Body` whose simple form is an empty vector.
11. Each kind a new type. "It's a new type and it carries all the data." (F`b7ba00/vision/messaging.md`, 2026-09-26) pulls toward one enum of kinds each wrapping a payload, against structs over chained variants. Written as `Message.[ Order.Body ... Psyche ]`: one variant layer over a shared struct.
