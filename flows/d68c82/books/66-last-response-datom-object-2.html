A flow's last response is the assistant text its harness records at the end of a turn. It has no type. The book page tooling reads one marked block inside it. When a turn ends, the Flow Nexus is told only that the turn stopped.

Verified on 2026-10-17 against Flow 67b80b3 (0.35.11, the version installed and running), Primary bda70b5, and field-context compensation/main-flow.md at 95121c6.

How it flows

The marked block

A presentation meant to become a book sits between two marker lines, and its first line inside is one datom naming the book (field-context compensation/main-flow.md, line 42):

<!-- to-the-living:start --> Presentation.{ «The last response as a datom object» }

Presentation.{ «title» } is the only datom in it. No ethos type declares Presentation; the title is matched as text. Everything outside the markers is machine output in prose.

Primary's tools/book-fetch.mjs finds the last complete block of the main thread:

export function latestBlock(records) {
  let latest = null;
  for (const [line, record] of records) {
    if (record.isSidechain || record.type !== "assistant" || !Array.isArray(record.message?.content)) continue;
    for (const block of record.message.content) {
      if (block.type !== "text" || typeof block.text !== "string") continue;
      const start = block.text.lastIndexOf(BLOCK_START);
      if (start < 0) continue;
      const end = block.text.indexOf(BLOCK_END, start);
      if (end < 0) continue;
      latest = { line, text: block.text.slice(start, end + BLOCK_END.length) };
    }
  }
  return latest;
}

Usage, from inside the flow whose transcript is read:

node tools/book-fetch.mjs --block
# stdout: <!-- to-the-living:start --> ... <!-- to-the-living:end -->

It reads Claude transcripts only: the session comes from CLAUDE_CODE_SESSION_ID or --session, the file from ~/.claude/projects/<project>/<session>.jsonl.

What the Flow Nexus learns at the end of a turn

Flow writes flow-hook into every Claude flow it launches. On Stop it reads hook_event_name and FLOW_ID and sends one datom; it reads nothing of the response (crates/flow/src/hook.rs):

let event = match self.event_name().as_str() {
    "SessionStart" => "Started".to_owned(),
    "PostToolUse" => match self.input.get("tool_name").and_then(serde_json::Value::as_str) {
        Some(tool_name) => format!("ToolUsed.{}", tool_name.quoted()),
        None => return HookCall::Nothing("PostToolUse without a tool_name"),
    },
    "Stop" => "Stopped".to_owned(),

};
HookCall::Report(format!("Report.{{ {} {event} }}", flow_id.quoted()))
flow 'Report.{ «d68c82» Stopped }'

On Stopped the Nexus reads the context size from the Claude transcript (see knowledge-refresh), then types the oldest queued request into the flow or puts it to sleep (crates/flow-nexus/src/waking.rs). No path in Flow reads, stores or forwards the response text.

Codex

A Codex rollout records the answer of a completed turn as payload.last_agent_message of its task_complete row, and the final text as a response_item with phase final_answer (knowledge-codex-rollout). No Primary tool and no Flow path reads either of them as a response object.

Two mechanisms carry a context threshold today. The Flow Nexus has two numbers per layer and reads one of them, only when it wakes a sleeping metaflow. Primary has a Stop-hook program with a warning size that no installed hook calls. No flow is refreshed while it is awake.

Verified on 2026-10-17 against Flow 67b80b3 (0.35.11, installed and running), meta-signal-flow a918b7d (the revision Flow pins), Primary bda70b5, and the running Nexus's Configuration reply.

fn resumes(context_tokens: Option<i64>, refresh_threshold: Option<i64>) -> bool {

field-context › compensation/launch.md

Launch a subflow through the harness's own flow mechanism. Do not nested-launch another harness to reach a model. A Primary starts only after a live Secondary for the same aspect and topic is verified; when none exists, the launcher starts that Secondary first and verifies its native binding before starting the Primary.

A flow that hands work to a Primary, or to any flow above it, first gathers through its own subflows everything that work needs: the living's words whole, his comments on the books, the records and the files. It sends all of it in one message. It never sends a pointer or an instruction to go and fetch.

A book the living asks for goes to a flow that can start it now; no launch, refresh or regeneration holds it.

Herdr is third-party software that we never modify.

Before reporting a launch as ready, verify its named Herdr session, colour, title, remote control, and its remote listing. Every spirit-* module and every intent-* module selected at launch goes in the flow system prompt, never the startup user prompt. Each subagent carries every spirit-* body in its own instruction layer.

A flow at or above its layer's configured refresh threshold receives no further work. A Fable flow receives no further work at 15% of its observed context window, or 100,000 observed tokens. Its secretary orders its successor started at once; the successor takes its topics from the handover. Read that threshold from the layer configuration. When the configuration or a supported context observation is unavailable, report that absence rather than inventing a value. Retire a predecessor only after its fresh successor has answered on a supported route and its native role and binding have been verified; then never reuse or message it.

Launch with the required permission mode. A permission prompt reaching the living is a launch failure. Escalate laterally at the same layer, then one layer up.

A lower layer that is unsure asks the layer above and admits what it does not know.

Psyche core Secondary is the hub: it decides what reaches a topic flow, and only matters of that topic do. Messages pass between Secondaries; a topic Secondary publishes its Primary's books. A flow that receives noise tells the sender it is noise and why; the sender finds why it misjudged, and that finding is proposed as a skill change.

A flow messages only whom its aspect, layer and topic allow, and refuses the rest.

A launched flow's startup task is never to reply READY. Its first response is a presentation of its context: subflows first reinforce that context, then the flow proposes how to make things better in its role, as named by the skills for its aspect, layer and topic. Psyche crystallizes its context into vision, intent and spirit; Mind for knowledge, questions and implementation; Field for its own roles.
