# A module names the role, not the host

Every setup gives its own values to hosts, users and paths, so a context module that names one setup's value is wrong everywhere else. This edition proposes that a module names the role or feature that selects a value, for any value that differs between setups. The new cluster role for the monitoring store is data, and went to its owner.

## Proposal 1: psyche-context › skills/vision-context-modules.md

+ A context module names a host, a user, a path or any other value that differs between setups by the role or feature that selects it in the system's data, never by the value one setup gives it.
