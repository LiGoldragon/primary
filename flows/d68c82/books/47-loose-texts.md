# Three texts that need a home

Three things you said live outside the vision modules, so no flow reads them where it looks. Each is proposed here for the module where it belongs.

## Proposal 1: psyche-context › skills/vision-aspects.md

+ There is a private part to everything: the private aspect talks to the private aspect below it, so the primary private talks to the secondary private.
+ The private part is served only through the open-source model.
+ The private part may ask its public counterpart sterilized questions: broad questions, as anyone might ask, with no name and no association.
+ Things that are tricky are talked over first in the private part. What a commercial model would accept is filtered before anything is asked, and what it would refuse is never sent to it, because that wastes context and can bring problems to the user.
+ When the line is crossed, the feedback corrects it. Every refusal is turned into a lesson, so nothing is wasted and the system adapts to the model.
+ The private part is chartered but not active. It does not filter private data and uses no provider until the open-source model runs it.

Ruling: land, amend, or reject.

## Proposal 2: psyche-context › skills/vision-model-roles.md

+ A role's allowed subagent models may be overridden in the specification. The first such exception lets the Publisher, a Haiku model, call the Sonnet Illustrator, one rung up; the Illustrator is a subagent of its own.

Ruling: land, amend, or reject.

## Proposal 3: psyche-context › skills/vision-context-modules.md

Raw is its own module type in your words, and a raw record's kind is decided only when it is distilled.

+ Raw psyche records live in psyche-context as their own module type, one file per topic in a folder named raw, beside the folders of the other module types; a raw record is given its kind when it is distilled.

Ruling: land, amend, or reject.
