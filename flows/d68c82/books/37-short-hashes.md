# Short hashes

A hash in a message is long noise. One rule already asks for six characters, but it ends with an escape, "when the receiver does not need more", and the committer's own brief asks for "the actual published commit". The brief wins.

| who sent it | messages with a full hash |
|---|---|
| the committer | 19 of 22 |
| Field | 73 of 185 |
| Mind seats | 14 of 24 |
| all seats, to this seat | 160 of 512 |

## Proposal 1: psyche-context › skills/vision/message.md, a new file

+ A hash or an identifier in a message is its first six characters.

Ruling: land, amend, or reject.

## Proposal 2: field-context › skills/compensation-prose.md

- A recipient message is plain sentences. Use no full hash, JSON header, timestamp, or repeated field; abbreviate an identifier to six characters when the receiver does not need more.
+ A recipient message is plain sentences. Use no JSON header, timestamp, or repeated field. A hash or identifier is written as its first six characters.

Ruling: land, amend, or reject.

## Proposal 3: field-context › skills/compensation-orders.md

- The result for a removal or deliverable names the commit, artifact URL, or other direct evidence that proves it happened.
+ The result for a removal or deliverable names the commit by its first six characters, the artifact URL, or other direct evidence that proves it happened.

Ruling: land, amend, or reject.

## Proposal 4: primary › tools/primary-committer/brief.md

+ Name a commit by its first six characters.

Ruling: land, amend, or reject.
