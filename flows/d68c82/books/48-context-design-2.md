# How a metaflow gets its context

Every reusable instruction lives as a module in the Psyche, Mind or Field context repository, and nowhere else.
A metaflow is started with the names of its modules and its first task, never with a file or a pasted text.
Curriculum turns those names into text: spirit and intent become the system prompt, and every other module goes once into the first message, followed by the task.
Flow alone starts and wakes a metaflow, and it accepts the start only when it sees every part arrive.
The texts that now live elsewhere are each moved, retired or held for you, and an original is deleted only after its content is compared.

## Proposal 1: psyche-context › skills/vision-context-modules.md

+ Every context module lives in one of the three aspect context repositories, Psyche, Mind or Field, and nowhere else.
+ A module exists only by being found in one of those repositories; a metaflow is given modules by name, never by a file or a passage of text.
+ A context text found anywhere else is moved into one of the three repositories.
+ Role modules and raw modules follow the same rule: their folder gives their type, their filename their subject.
+ Orders and handovers written for one launch are work data, never context.
+ Each text found outside the three repositories is moved, retired or held; its content is compared before the original is deleted, and a held text waits for the living.

Ruling: land, amend, or reject.

## Proposal 2: psyche-context › skills/vision-context-modules.md

+ A role module is a component: it is composed into the context of a main flow or a subagent and never becomes a skill.
+ Which modules a role receives is stated by that role's definition.
+ A role's modules are added to its aspect's defaults and never remove one.
+ A role's subagent definition is composed from its module names alone, as a metaflow's startup is.

Ruling: land, amend, or reject.

## Proposal 3: psyche-context › skills/vision-context-modules.md

+ A metaflow's whole context is given to it as text when it starts: spirit and intent as its system prompt, every other module in its first message.
+ The first message names every module it carries and tells the metaflow these are its skills, given here, not to be reloaded.
+ Each module is given once, after the modules it depends on.
+ A first message too large to send whole is split between modules and sent in order, with the first task in the last part.
+ A metaflow that wakes fresh is given the same context again.
+ Flow alone starts and wakes a metaflow; any other launcher only hands the request to Flow.
+ Flow confirms a start by reading the metaflow's record: every part present, in order and unchanged, and the first answer given at the intended model and effort.

Ruling: land, amend, or reject.

## Proposal 4: psyche-context › skills/vision-context-modules.md

+ Nothing enters a starting metaflow's context but its composed modules and its first task.
+ The first task is the only free text a starting metaflow receives.
+ No skill or command is loaded at start, and no file is handed to a metaflow by its location.

Ruling: land, amend, or reject.

## Proposal 5: psyche-context › skills/vision-context-modules.md

- A module declares its placement: the system prompt, or loaded on demand. A skill is the harness's interface for an on-demand module.
+ A module declares its placement: the system prompt or the metaflow's first message.
+ Loading a module on demand, through a skill, is long term.

Ruling: land, amend, or reject.

## Proposal 6: psyche-context › skills/vision-context-modules.md

+ A role's data holds its identity, model, tools, permitted callers and module names, and no instruction text.
+ Every instruction a role follows comes from a module.

Ruling: land, amend, or reject.

## Proposal 7: psyche-context › skills/vision-model-roles.md

+ A right to call a model or a role is enforced by the caller's registered identity, never by wording in a prompt.

Ruling: land, amend, or reject.
