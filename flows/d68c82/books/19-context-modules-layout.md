# Context modules: folders, types, placement

```
 +-----------------------------+
 | psyche-context              |
 |   skills/   vision, intent, |
 |             spirit          |
 |   vision/   ethos only      |
 | mind-context                |
 |   skills/   knowledge,      |
 |             operation       |
 | field-context               |
 |   skills/   compensation    |
 +-----------------------------+
     |
     v
 +----------------------+
 | Curriculum: a file   |
 | in vision/ is named  |
 | vision-<subject>     |
 +----------------------+
     |  every module
     v
 +----------------------+
 | a skill, loaded on   |
 | demand               |
 +----------------------+
     |  and a few, chosen
     |  in launch lists
     v
 +----------------------+
 | the system prompt    |
 +----------------------+
```

Every context module is a skill today. The system prompt carries a few of them as well: spirit, the intents on context modules, the main flow and the psyche, and, for Psyche seats, the book modules. Launch lists for each aspect choose them; no module says where it belongs.

Only one module, Ethos, sits outside a skills folder, in psyche-context's vision folder. The code that reads that folder is development work in Curriculum, not yet committed.

The type is written twice: in the folder or repository, and again in the file name.

## Crystallization

### Proposal 1: The folder names the type

File: psyche-context/skills/vision-context-modules.md, at the end

```
 +--------------------------------+
 | psyche-context                 |
 |   spirit/  intent/  vision/    |
 | mind-context                   |
 |   knowledge/  inquiry/         |
 |   operation/                   |
 | field-context                  |
 |   compensation/                |
 +--------------------------------+
     |
     v
 +----------------------+
 | a file is named by   |
 | its subject; its     |
 | folder is its type   |
 +----------------------+
```

+ A context repository holds one folder per module type; no folder is called skills. A file is named by its subject alone, and its folder gives its type.

Ruling: land, amend, or reject. Proposal 4 of «Subflows: kind, role and level» is carried here.

### Proposal 2: A module declares its placement

File: psyche-context/skills/vision-context-modules.md, at the end

+ A module declares its placement: the system prompt, or loaded on demand. A skill is the harness's interface for an on-demand module.

Ruling: land, amend, or reject.

### Proposal 3: A request is answered with a review

File: psyche-context/skills/vision-context-modules.md, at the end

+ A request from the living is answered with a module to review: a compensation, an inquiry or a knowledge module. These are deployed before he reads them; a vision or intent line waits for his approval.

Ruling: land, amend, or reject.
