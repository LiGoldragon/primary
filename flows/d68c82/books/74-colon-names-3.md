# A module's kind shows in its name on old tech

### Proposal 1: old tech names a module kind:name · psyche-context › vision/context-modules.md

  A context repository holds one folder per module type; no folder is called skills. A file is named by its subject alone, and its folder gives its type.
+ Where old tech names a module by a directory, a file name or a harness skill name, none of which carries a space, the name is kind:name, as vision:book, so its kind shows.
  A context repository holds one section of role modules per layer, Primary, Secondary, Tertiary and Quaternary, and may hold sections for specialized topics.

```
+-------------+ +-----------+ +--------------+
| directory   | | file name | | harness      |
|             | |           | | skill name   |
+-------------+ +-----------+ +--------------+
       |              |              |
       +--------------+--------------+
                      |
                      | names the module,
                      | without spaces
                      v
           +---------------------+
           | vision:book         |
           +---------------------+
              |               |
              | kind, before  | name, after
              | the colon     | the colon
              v               v
        +-----------+   +-----------+
        | vision    |   | book      |
        +-----------+   +-----------+
```

Ruling: land, amend, or reject.

### Proposal 2: every flow reads kind:name · psyche-context › spirit/core.md

  Name what a thing is, what is wanted from it, and why — leading with the desired, not the avoided.
+ A module named kind:name reads as its kind before the colon and its name after it: vision:book is the module book, of the kind vision.
  Target the best end-shape, not the historically practical compromise.
