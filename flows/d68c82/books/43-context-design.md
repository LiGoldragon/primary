# How a seat gets its context

Flow is being rewritten so that a seat starts with its whole context already in hand.
A seat is started with its address, its model and effort, two lists of module names, and its first task; nothing else.
Curriculum composes the named modules into text, Flow checks it, and the seat receives it at once.
Curriculum cannot yet compose to text on request; Mind is adding that now.

| Part of the seat's context | What it carries |
| --- | --- |
| System prompt | Spirit and intent modules |
| First message | Every other module, role modules included, then the first task |

## Proposal 1: psyche-context › skills/vision-context-modules.md

+ Every context module lives in one of the three aspect context repositories, Psyche, Mind or Field, and nowhere else.
+ A module exists only by being found in one of those repositories; a seat is given modules by name, never by a file or a passage of text.
+ A context text found anywhere else is moved into one of the three repositories.

Ruling: land, amend, or reject.

## Proposal 2: psyche-context › skills/vision-context-modules.md

+ A role module is a component: it is composed into the context of a main flow or a subagent and never becomes a skill.
+ Which modules a role receives is stated by that role's definition.

Ruling: land, amend, or reject.

## Proposal 3: psyche-context › skills/vision-context-modules.md

+ A seat's whole context is given to it as text when it starts: spirit and intent as its system prompt, every other module in its first message.
+ The first message names every module it carries and tells the seat these are its skills, given here, not to be reloaded.
+ Each module is given once.
+ A first message too large to send whole is split between modules and sent in order, with the first task in the last part.
+ A seat that wakes fresh is given the same context again.
+ Flow confirms a start by reading the seat's record: every part present, in order and unchanged, and the first answer given at the intended model and effort.

Ruling: land, amend, or reject.

## Proposal 4: psyche-context › skills/vision-context-modules.md

+ Nothing enters a starting seat's context but its composed modules and its first task.
+ The first task is the only free text a starting seat receives.
+ No skill or command is loaded at start, and no file is handed to a seat by its location.

Ruling: land, amend, or reject.

## Proposal 5: psyche-context › skills/vision-context-modules.md

- A module declares its placement: the system prompt, or loaded on demand. A skill is the harness's interface for an on-demand module.
+ A module declares its placement: the system prompt or the seat's first message.
+ Loading a module on demand, through a skill, is long term.

Ruling: land, amend, or reject.
