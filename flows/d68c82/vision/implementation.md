
## An approved vision is implemented, cycling until it aligns

> Every time I state I approve a new vision, it has to go and get implemented for the current implementation. Or a question has to be brought back to me as to how we want to implement this, actually, because there's a lack of clarity there, maybe.
>
> Otherwise, a presentation is made by Astra [in Mind] as to how this should be implemented, like in a presentation with flowcharts, so I can review it. Then the implementer will implement it like that. Astra or Sol can do the first implementation, and then it has to be reviewed by Psyche, secondary and/or primary in some cases.
>
> If I specify that primary should do the audit too against [the vision] and/or any clarifications that I made on that vision, there's an ongoing cycle until the vision aligns. After the audit is found to be aligned, the implementation is found to be aligned with the vision. There's a cycle going on when I approve a vision: "Let's do a back audit of the last few days and see what has been implemented, what hasn't, and let's start catching up on that."
>
> If there are big topics, there should be a topic for each implementation. Whatever it is that's being implemented, like ethos or whatever, there's a mind topic flow for that so that it can specialize on that. The core is going to manage communication between them so that there's no noise.
