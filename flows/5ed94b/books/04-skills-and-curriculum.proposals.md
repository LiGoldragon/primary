Presentation.{ «Skills and Curriculum» }

Skills are the distilled vision written down as context modules: vision, intent, spirit, knowledge, operation. Curriculum is the tool that generates them for each harness. He wants one stored copy, a kind on every skill, a steady stream of small edits, and no model names in the text. Each proposal is one edit to one module. Answer with the number, and "1" or "2" where there are two texts.

**1. Where the text is written**
Vision, module skill-designing. Edit. His records pull two ways.
Text 1:
> Skills are written in the three skill repositories (psyche, mind, field) and copied from the vision.

Text 2:
> The distilled records are the source. Skills are generated straight from them, and what he says is stored once.

Rests on: 3 Oct, "Why are skills not living in three repositories" (text 1); 3 Oct, "the data ends up in the skill" (text 2).

**2. Where the kind is declared**
Vision, module skill-designing. Edit.
Text 1:
> The folder carries the kind. A repository has a kind, assigned centrally.

Text 2:
> Each skill carries its kind in a typed record, never copied from a directory name. The generator adds the kind prefix from it.

Rests on: 24 Sep (text 1); late Sep, "Just copying the directory name is dirty" (text 2).

**3. Homes for the unprefixed skills**
Vision, module skill-designing. Edit.
> What he wants the result to be is vision, under psyche. What is true of a tool is knowledge, under Mind. How a recurring job is done is operation, under Mind. Compensation and trial stay under Field.

Rests on: 28 Sep; 2 Oct, "Documentation becomes knowledge". The book's table assigns the 39 skills by this rule.

**4. A skill leans only upward**
Vision, module skill-designing. Edit.
> A skill may depend only on its own kind or a higher one. Vision depends on intent, spirit or vision. Operation depends on vision or anything higher. Trial sits at the bottom.

Rests on: 29 Sep.

**5. Skills speak in layers**
Vision, module skill-designing. Edit.
> No skill names a model. Skills say primary, secondary, tertiary and quaternary.

Rests on: 3 Oct, "all the skills refer to layers".

**7. More than one source**
Operation, module trial-generated-projection. Edit.
> Curriculum takes more than one source of the same kind, so people bring their own and borrow others'. It refuses to write when two sources define the same skill.

Rests on: 3 Oct.

**8. A recurring failure is a missing line**
Operation, module trial-recurring-failure. Edit.
> When the same thing goes wrong twice, the fix is a line in a skill. Skill edits are proposed as a steady stream of small proposals, each answerable with a yes.

Rests on: 3 Oct, "every time there's a failure like that, it means that something wasn't written".

**9. Context modules**
Knowledge, new module context-modules. Create.
> A skill is one kind of context module. The same module can go in the system prompt, in the prompt, or stay loadable. Flow keeps a registry of modules by kind, name and location. A launch names, per kind, the modules it wants. Curriculum implements the same standard.

Rests on: 3 Oct.
