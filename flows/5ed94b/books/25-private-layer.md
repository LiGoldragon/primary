Presentation.{ «The private layer» }

The part of the system that holds what is his alone, the model that serves it, and the two pieces beneath it: Criome, which proves who is who, and Persona, which runs everything. A commercial model here means one rented from a company, such as Claude or Codex. An open-source model is one whose weights anyone may run on their own machine.

## Part 1. What he wants

### Every layer has a private part

Each layer of agents has a private half beside its public half. The private halves speak to each other, top to bottom, apart from the public ones.

> "Actually, there's going to be a private part to everything, I think, because the private aspect talks to the private aspect below it, right? The primary private talks to the secondary private, and we are actually talking about the model."

-- 14 September

### The private part is the soul

Every person gets a thinking-machine system of their own, and its private part has a name.

> "The idea is that people have their own cluster, their own thinking machine system, personalized to them. We're going to create this private layer, the soul, basically. We could call it that: the soul. It's like the private part of the persona."

-- 13 September

The soul gives the system its personality and runs the basic security, so the commercial models are not asked to do what they handle badly.

> "I want a core soul cluster that's going to give the personality and drive the basic security measures of setting all this up so that the models here who have a hard time doing this stuff don't have to do it. The models that can do it can do it on an open source harness that we control better."

-- 17 September

It keeps its own repository, separate from the public one.

> "Let's develop the private aspect of all this so that we have a private repo for the soul, the core layer. Let's set up the private layer, the core layer."

-- 18 September

### The deepest layer holds the private information and guards the rest

The innermost layer, layer zero or the core, holds everything private and checks that a request is meant, not malicious, and really from him.

> "We're going to create a layer, layer 0, which is self-hosted and has all the private information. It's mostly just a double-check of intent, non-malice, and true source."

-- 14 September

It reviews code before any update for malice.

> "It's inside the system, and it has to approve that there's no malice before doing an update, so it can review the code to look for malice, which is not hard for a security review of a thing."

-- 14 September

### Served only by an open-source model

No commercial model ever serves the private layer.

> "The private layer is only served through the open-source model, and it can use the public counterpart with sterilized questions, basically broad questions, like if someone were to ask."

-- 14 September

The reason is that it must be possible to host it yourself.

> "The private part is because the whole idea is that it can be self-hosted, so it has to stay on self-hosted or self-hostable open-weight models."

-- 14 September

The model is chosen for doubt and care, and its provider for a good name on privacy.

> "We're going to have to figure out which model we want to pick and where we're getting provider-provided API access for this open source model. Do some research into that: which one has good goodwill in terms of privacy and security"

-- 13 September

His first pick was Kimi K3, run through OpenCode, a harness that can drive any model.

> "Yeah, Kimi K3 on OpenCode sounds great. Let's set that up."

-- 14 September

A rented provider is a stage, not the end. A kernel process on a machine dedicated to him rules the soul, wherever that machine is.

> "The Soul is going to run on everything, but it's going to be ruled by a kernel process that runs. This is one of the modes that you can use, and you can pick a private provider, even in the cloud."

-- 13 September

Proposed: the open-source model first runs through a provider chosen for privacy, and moves to his own machine once one is big enough.

### Thinking out loud, downward

The private layer may hand thinking down to a commercial model once the idea, put in general terms, is no longer private.

> "This zero layer, this core layer, is what runs, ostensibly, on the more private server, self-hosted, open source, which can, of course, outsource jobs down into frontier models for thinking about things if it deems that it needs to think about something. There's a certain point at which an idea is not so private in its abstract form."

-- 14 September

### How a question is sterilized

A question sent down carries nothing that points back to him.

> "There's no name, there's no association"

-- 14 September

Proposed: the private model rewrites the question as a stranger might ask it, removing every name, place, account, number and relationship. It then asks whether anyone could tell whose question it is; if so, the question stays private. The answer returns to the private layer, which puts the particulars back.

### Nothing that would be refused is sent

The private layer knows what each commercial model refuses, and a refusal can cost him, up to a suspended account.

> "it can know what FrontierModel does refuse, which could also bring problems to the user."

-- 14 September

So hard subjects are talked through privately first, and only what a commercial model will accept is passed on.

> "Things that are tricky are talked to first on the private layer, and the things that are acceptable to commercial models are filtered before anything is asked, because it knows what things would be okay and what's not."

-- 14 September

> "For anything that would be refused, it shouldn't go to these models, just because it's a waste and it creates waste of context."

-- 14 September

### Every refusal becomes a lesson

When the filter misjudges and a question is refused, the refusal corrects the filter.

> "If it does cross that line, it'll get feedback to correct it."

-- 14 September

> "Everything is turned into a lesson so that it's not wasted, and we adapt to the model. It's training, it's guide rails, and however they control the models to not respond to some things or to take action if some things are asked."

-- 14 September

Proposed: each refusal is written down privately, per model, with the general form of the question; the filter reads this list before every send.

### What never goes to a commercial model

Secrets, even on the public side, are not trusted to agents that publish.

> "Right, even on the public part, there is private data, like tokens, that the public, meaning they push to public repos, shouldn't be trusted with too much, in case they put it in a repo publicly facing stuff."

-- 14 September

Proposed: never sent are his name and the names of people near him; his accounts, keys, tokens and phone number; his home, his cameras and their recordings; anything that ties a question to him; and anything the refusal list says would be refused.

### Criome, the cryptographic biome

Criome is a network built on cryptography, and the heart of the work.

> "The criome is sort of like the concept of this web based on cryptography. It's like a cryptographic biome. That's why it's criome."

-- 14 September

> "The criome is all we're talking about all the time. That's what we're making."

-- 20 September

Every layer runs its own Criome process with its own key, and he authorizes from a cold key on his phone or a hardware wallet through the Unity app.

> "Every layer is going to have its own criome process running, which has its own key. The app on my mobile or on my Ledger, maybe if we make our own app, to get a cold criome key that can ask for authorization through the Unity app on the phone or on the laptop, right?"

-- 14 September

It replaces SSH.

> "This is actually one of the most important pieces because it gets us our own authentication system so that we can bypass SSH."

-- 14 September

Its trusted machines are his private network.

> "The criome cluster is the trusted network, and that's the tailnet. Those are the trusted nodes based on the trust value there in the cluster."

-- 19 September

### Persona, the machine person

Each living person has a Persona: a thinking machine of their own.

> "which is why, essentially, every living person has its own persona, its own machine. It's a machine person. Machina persona, right? Persona is short for that."

-- 1 October

A Persona is one whole, not one machine.

> "Yeah one persona is not one machine. One persona is one unified whole that could spawn multiple machines but persona is how these different identities are addressed. Ultimately one machine can run parts of several personas."

-- 25 September

It manages every cluster and layer.

> "So, by default, the persona component manages all of the clusters, the different layers."

-- 15 September

Its first job is to keep the services alive.

> "Maybe that's what the first use of persona is: it checks all the services and makes sure they're running."

-- 23 September

Proposed: Persona owns which seats run and where; Criome owns who may do what; the soul owns what is private. The soul runs inside the Persona and signs with its own Criome key.

### Chartered, not active

The private layer waits for its open-source seat. Until it runs, the Claude and Codex pair is the public part only, and nothing is filtered.

> "Yeah, we're just doing everything public for now. We're gonna work towards creating a separation of private data."

-- 10 September

## Part 2. What exists today

Witnessed on 3 October 2026.

- The standing rules say the private part is chartered and not active until its open-source seat runs; the Claude and Codex pair is the public part only.
- No open-source model is configured for any seat. OpenCode runs on this machine with no model or provider set; its test server keeps failing and restarting.
- Prometheus, the machine once reported to hold a large open model, shows offline on his private network and did not answer.
- Criome exists as code: today a small signing and attestation service. Persona exists as code: the manager that wires the parts together. Neither was running here.
- There is no private repository for the soul. Everything is still public.
