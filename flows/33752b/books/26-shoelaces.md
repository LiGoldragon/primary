# Tripping over the shoelaces

```
   you change how a thing works
              |
   "stop doing X"  (an order to remove)
              |
   +----------+-----------+
   |                      |
 carried out          kept as a rule
 X removed            "never X" stays
 order ends           in the skill
   |                      |
 clean                 + "never Y"
                       + "never Z"
                       + ...
                          |
                    rules the machine
                    reads every turn,
                    about things that
                    no longer exist
                          |
                    noise; the next
                    rule gets lost;
                    naming X primes X
```

## What the prominent have said

Willison, 2025, on a vendor system prompt: it reads as "a detailed list of all of the things the model used to do before it was told not to do them."

Anthropic, Claude Code guidance: when a rule keeps being broken, "the file is probably too long and the rule is getting lost"; for each line ask "would removing this cause Claude to make mistakes?"; "a clean session with a better prompt almost always outperforms a long session with accumulated corrections"; say what to do, not what not to do; corrections written for an older model make a newer one overtrigger.

OpenAI, GPT-5 guide: a model given contradictory rules "expends reasoning tokens searching for a way to reconcile the contradictions"; conflicting rules resolve toward the end of the prompt.

Fried and Hansson, Rework: "Policies are organizational scar tissue … codified overreactions."

Wegner's ironic process and the "pink elephant" result: naming the forbidden thing primes it.

Interpretability work: a suppressed behavior is not removed; "unlearned" knowledge comes back with a few examples; one refusal direction fires on harmless prompts too.

The counterpoint: a curated list of lessons helps when each item is kept on its own merit; rewriting it wholesale loses them.

## Distillation

### Proposal 1: the term

A standing rule says what the system is. An order to remove something is not a rule; it is carried out and then gone. The nearest existing word is the database **tombstone**: a marker that says "this is deleted", kept only until every copy has seen it, then purged. Also found: repeal, sunset clause, compulsory deprecation (a removal with a deadline). Options: (a) tombstone; (b) repeal; (c) a word of yours.

### Proposal 2: vision-distillation, new section

Target: psyche-skills, vision-distillation, after «No useless negatives».

Added:

**A removal order is not a rule**

An order to stop doing something, given to change how a thing works, is carried out and then gone. It is not kept as a standing negative in a skill. What remains in a skill is what the system is.

## Question 1

When you give a removal order, where does it live while it is being carried out? In the flow log of the flow that heard it, with the check that shows the old way is gone, and nowhere else?

## Question 2

Do the existing negatives in the skills get sorted now, each either a removal order whose work is done, to be deleted, or a real rule, to be kept and written positively? That is a sweep of the same kind as the cleanup, and it would be the next book.
