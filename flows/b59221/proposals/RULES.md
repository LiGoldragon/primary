# How each proposal is drafted

- One file per proposal, in /home/li/primary/flows/b59221/proposals/<slug>.md. One subject: the module it lands in (a few are ruled to touch two modules; then the title names both).
- Title line `# <title>`, then the subtitle `*Created by Opus, drafted by Sonnet.*`.
- Belief lines only: what the module removes and what it adds. No sequence of work, no test, no check, no question, no history of what went wrong. Those are beads, never in a proposal.
- Removal before addition. A removed line is quoted exactly as it stands in the module today (read it in /git/github.com/LiGoldragon/psyche-belief/<type>/<subject>.md), under `## Removed, from <type>:<subject>`, shown beside the line that makes it unnecessary. Additions under `## Added, to <type>:<subject>`.
- Each added line is a plain present-tense statement of what is and what is wanted, positive, self-standing, every term defined. Fewest plain words.
- Code where code says it: Ethos (vertical layout, a comment on each line that opens a next layer), datom, Nix or Rust, in fenced blocks with no file path. Every type named is shown in full: added, or shown as it already stands in its module.
- A mermaid flowchart only where the proposal has a shape (adds, removes, keeps); it goes under the addition heading.
- A line that is the living's ruling is marked: a line `Pre-approved, his words: "<his words verbatim>"` directly under it. Other lines carry no mark; they wait on him.
- Do not commit, do not publish. Return the full text of each file and its path.
- Modules live in /git/github.com/LiGoldragon/psyche-belief: spirit/, intent/, vision/, knowledge/ (a marked horizon module is e.g. vision/far-versioning.md or vision/long-unity.md; check how existing marked modules are named and follow that; say if the module does not exist yet, then the proposal creates it).
