# Startup hash exposure audit

The authored launcher added machine digests to model reading text. The exact offending fragments were `SHA-256: \`${s.sha256}\`` in the Codex source wrapper, `SHA-256: \`{item['sha256']}\`` plus `BOOTSTRAP_READY ` followed by `payload_hash(...)` in the Claude refresh wrapper, and `sha256="..."` source attributes plus `Payload SHA-256: ...` in the single-turn Claude builder. The user correction applies to those wrapper fields: their bytes are useful for verification but have no semantic role in a flow's reading prompt.

The three builders now present source paths and source bodies without generated hash fields. The Claude refresh asks for plain `BOOTSTRAP_READY`; its refresh receipt still carries the payload digest. The bootstrap controller independently compares that receipt digest with its frozen manifest, and batch refresh checks the plain acknowledgement plus the presence of the receipt digest. The Codex plan, native receipt, and rollout checks retain source, skill, and prompt digests outside the prompt. The single-turn builder retains its pinned-source checks and prepared receipt hashes outside the prompt.

The smallest relevant witnesses passed: `native-seat-launch.test.mjs`, `claude-native-seat-refresh.test.py`, `claude-bootstrap-controller.test.py`, and `native-batch-refresh.test.mjs`. A separate in-memory `claude-single-turn-start.py` assembly fixture confirmed source and prior-turn content were present, generated hash wrappers absent, and the prepared receipt still matched the exact prompt. No live seat was launched or restarted.

Hash exposure remains possible through selected **source bodies**. The current Field Sol profile formerly loaded the `flows/8565e8` morning and compatibility reports, both of which contain full commit revisions and operational commands. It now loads `flows/6db4fe/reports/field-sol-startup.md`, a compact account of the same open work with paths to the original evidence for operations that need exact pins. A fresh `--prompt` assembly for that current profile had no `SHA-256`, `sha256`, or 16-or-more-character hex match. The current Field Astra prompt's sampled output also had no such match. Other configured role manifests in `native-seat-launch.mjs` select historical handoffs, source manifests, and JSON receipts containing full digests; the specifically named `field-sol-of-395aed` profile retains its predecessor's historical source set. The archived `flows/33ba2b/handoff/field-astro-voice-source-manifest.md` is a dense example; `flows/cf3553/summary.md` contains hashes and session identities. Existing assembled handoffs under `flows/b49251/handoff/psyche-medium-v1/` also contain source hash attributes. These records were left intact. A future source-selection pass should supply lean semantic handoffs to other new seats and keep operational pins in queryable receipts; it should decide individually which revision is needed for the work. This audit does not establish that every possible source body is hash-free.

`tools/compose-refresh-prompt` prints its digest to stderr for the submitter, outside the composed prompt. `tools/extractor/extractor.py` writes source digests into extracted evidence, which could become reading noise if selected as a source. `tools/prompt-relay`, `tools/fan-out.mjs`, and native verification code use hashes for transport or receipts; the inspected direct prompt assembly paths do not print those values into model text. No bulk historical record rewrite was made.
