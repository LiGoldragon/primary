# Bounded independent testing worker in Curriculum

Canonical authored Curriculum revision `c9c39549` adds a `tester` alias in `/git/github.com/LiGoldragon/Curriculum/roles.datom` and extends `/git/github.com/LiGoldragon/Curriculum/skills/testing.md`. The alias is `write trivial`, available to Codex and Claude. The current role mapping projects Codex `tester` to `gpt-5.6-luna` at medium effort and Claude `tester` to `claude-haiku-4-5` at medium effort. Its catalog description tells a worker given only a bounded target, immutable revision, authority limits, and acceptance contract to choose the procedure, fixtures, negative cases, and independent oracle. The testing skill adds the detailed method and prevents status-only production wakes. The invoker should not supply copied implementation assertions as an oracle.

A disposable `curriculum-deploy Visualize`, `Generate`, then `Check` against an empty temporary workspace parsed the source and returned 66 skills and 23 role packets. Inspecting the generated tester role proved the Luna model/effort and catalog description. It also proved the current limitation: the generated tester `developer_instructions` does **not** contain the detailed testing skill. This source is therefore **authored and projection-tested, not installed or native-expanded**. Primary's generated trees were not edited or regenerated by this flow.

The consumer needs a typed alias-specific skill association, not a universal module. Minimal data contract: the tester alias names the `testing` skill source by stable ID; the assembler resolves only that owned authored source, injects its body into the tester role's native instruction/skill surface, records source revision and digest, and refuses missing/ambiguous IDs. Existing role aliases without the association retain their current composition. A `RoleAlias.skill_ids: Vec<String>` field or an equivalent separate alias-to-skill mapping would express this; the precise schema/version migration belongs to the consumer and Mind owners. Current `roles.datom` lacks such a field, so no automatic native skill loading is claimed. 03 owns eventual scoped projection and native expansion receipt after that consumer change and namespace-safe output plan. The role is a reusable worker definition, not twelve new native seats.

No Flow/Message/Nexus source or production runtime was changed for this work.
