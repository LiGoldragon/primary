# Claude context and usage observation

Claude Code 2.1.263 is installed locally. The strongest native live source is the statusline JSON that Claude Code passes to its configured command. It carries an exact `session_id`, `context_window` occupancy and size, current request cache breakdown, and (for eligible plans after a response) five-hour and seven-day rate-limit percentages and reset times. It updates on assistant messages, compaction, selected UI changes, reset times, and an optional timer. This is a supported, no-token interface. The local `~/.claude/statusline.sh` consumes that JSON but does not persist it, so its past raw values cannot be recovered read-only. The `claude-statusline-publish.mjs` wrapper is prepared but is **not installed in settings**. It writes only projected metadata under a chosen directory, keyed by exact session ID, then invokes the existing display command with the original input. Integrating it in a live statusline requires a separately scoped settings change and a target directory.

The immediate passive fallback is the native JSONL transcript for the registered `native_thread`. `claude-context.mjs` reads at most 512 KiB from its tail and projects only assistant `message.usage`, model, timestamp, and later invalidating record kinds. It does not return message text. Latest request `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` is an input-token **proxy** for context at that response. The model's context-window size and exact used/remaining percentage remain unknown from this source. A later user prompt, summary/compaction boundary, or incomplete record marks prior occupancy unknown. File modification time alone is not a new model response. Output tokens are per request, not current occupancy; cumulative session token totals would be a different metric.

The collector accepts `{nativeThreadId, transcriptPath, statuslinePath, now}` and returns `{source, method, observedAt, eventAt, nativeThreadId, model, occupancy, usage, quota, freshness, errors}`. `occupancy.status` is `exact` only for a fresh exact-session statusline percentage; `proxy` denotes transcript input tokens after the last complete assistant response; `unknown` means no defensible current estimate. Missing fields remain `null`. `usage.scope` is `last-request`, with uncached input, cache creation, cache read, output, and summed input tokens. `quota` is account-level and present only from statusline windows; its percentages are consumption, not context. `freshness` names response-observed, superseded, partial, or current-snapshot and reports age. Nexus should preserve `observedAt` separately from `eventAt`, merge only exact native identity matches, and avoid treating idle UI state or a stale transcript as current capacity. The publisher's current-five-minute freshness limit is a conservative collection policy, not a Claude guarantee; idle statusline state may remain valid beyond that age, so a durable event store should retain last-known values with their timestamp and explicit stale state.

Other viable sources and limits:

| Method | Data | Boundary |
| --- | --- | --- |
| Claude Code statusline stdin | Exact context %, window size, token components, rate-limit windows, model, session ID | Best live feed; requires a configured publisher to persist; fields can be absent/null before first response or after compaction. Rate-limit windows can disappear at reset. |
| Exact-session JSONL metadata tail | Last assistant request usage and model, with timestamp | Passive and immediate; no official window size/percentage or account quota; record schema is native persistence, not a public monitoring API. |
| CLI `--print --output-format=json/stream-json` and Agent SDK streaming | Result or message usage for flows launched and owned through that route | Requires starting/controlling a model flow. Resuming an existing session would add work or fork; never use for passive inspection. |
| OpenTelemetry export | Token/cost metrics, API events, compaction event, correlated session ID | Supported for future configured launches; exporter setup is required. Metrics describe consumption, not current context occupancy or subscription quota. |
| Interactive `/usage`, `/context`, `/cost` | User-facing plan, context, and cost views | Sending commands to a running pane changes session interaction; not used by this read-only collector. `/usage` can display last-known bars after its upstream request fails. |
| Local stats cache, daemon/job state, displayed terminal line | Aggregate or presentation state | Not an exact authoritative context/limit feed; rendered statusline may floor percentages and map missing values to zero. No credential or undocumented quota endpoint was queried. |

## Tests and live witness

Six Node tests passed. They cover exact request-token arithmetic, newer prompt and compaction invalidation, exact-session statusline occupancy/quota, post-compaction null occupancy, rejected mismatched statusline and partial JSONL, and metadata-only publisher passthrough with mode 0600. The publisher test first failed because the fixture used `/bin/cat`, absent on this Nix host; using the `cat` on `PATH` passed. A live read through three exact HM-registered Claude thread IDs succeeded with the 512 KiB cap: one response had 609,736 input tokens, one had 133,208, and one earlier response had 192,687 but was superseded by a later prompt. These are last-request input observations, not certified current window percentages. The direct read ran without invoking Claude or modifying its settings or sessions. Transcript JSONL sometimes includes records without `sessionId`; the collector ignores those rather than calling them identity conflicts.
