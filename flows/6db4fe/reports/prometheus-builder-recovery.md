## Causal addendum — bounded follow-up

Ouranos's Yggdrasil service is active and has not restarted. Its own journal identifies the lost transport: Prometheus and Zeus were both directly connected through IPv6 link-local sessions on Wi-Fi `wlp0s20f3`, then timed out when that path disappeared. Later wired/USB listener activity is visible, but no replacement peer session was observed. One bounded control ping each to known Ygg peers Zeus and Tiger received no reply, so the failure is broader than the configured Prometheus SSH name. The Ygg admin socket is owned by the service's dynamic user and denied this account; no peer-table claim was made.

The saved `goldragon.criome` Wi-Fi profile remains autoconnecting, but NetworkManager repeatedly reports association timeouts. The radio is not rfkill-blocked; one bounded scan found 13 other networks and **did not find that SSID**. Another activation would repeat an ongoing failed attempt and could alter routing, so none was made. The router source can provide a cluster SSID through hostapd, but the absent SSID alone does not prove whether the peer access point, peer host, distance, or local reception is responsible. This is the specific next peer-side access dependency.

The USB NIC identifies as an ASIX AX88179A using `cdc_ncm`. Sysfs reports carrier 1 and 1000 Mbps, zero RX packets/errors, and zero TX errors. Kernel logs show its interface rename, while the wired uplink recovered from a brief link flap and remains the default route. This rules out an observed local driver error, but carrier without incoming frames still cannot identify the far endpoint or establish Prometheus health.

`/etc/nix/machines` has exactly one authorized builder line, for Prometheus. The CriomOS builder module emits `ssh-ng` build machines from the configured builder set. No other live builder was present in the installed dispatcher mapping; no alternate host was silently selected or contacted. The existing NetworkManager share and its earlier rollback remain unchanged. There is no evidence-backed local network repair while both the target Wi-Fi SSID and peer traffic are absent; inspect Prometheus or its AP/NIC/power through an already-authorized local management path before another activation or remote build attempt.
