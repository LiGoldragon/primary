# Source-only CriomOS USB IPv4 gateway consumer

Observed 2026-09-21 for Field flow `6db4fe`, Orchestrate lock #4017. Source branch `usb-gateway-consumer-6db4fe@origin`, commit `9842f51a` in CriomOS. No NixOS activation or live network mutation was made in this source lane.

The verified Horizon **serializer fixture** is `{"usbIpv4Gateway":{"downstream":"enp0s20f0u1c2","downstreamMac":"00:0e:c6:33:4f:97","gateway":"10.44.0.1/24","uplink":"enp0s31f6"}}` (Horizon producer `37416e10`, `flows/753e69/reports/usb-gateway-json-fixture.md`). CriomOS's existing node-service helper consumes flattened `{kind = "..."; ...}` records. The new consumer accepts either this verified externally tagged serializer shape or the existing normalized kind shape, with exact fields and at most one gateway service. **The actual materialized Lojix `horizon.node.capabilities` record has not been witnessed.** Support for both shapes is a source compatibility proposal, not proof of the final projection.

`modules/nixos/network/usb-ipv4-gateway.nix` is imported by the network module. When absent, it adds no profile or firewall-backend setting. When present, it checks the interface names, distinct uplink/downstream, unicast nonzero MAC, IPv4 host CIDR, required NetworkManager, absence of networkd ownership and generic NAT, an enabled iptables firewall, and no other declared shared profile. A local NixOS option `criomos.usbIpv4Gateway.profileUuid` supplies **migration state**, not a new Horizon service field: a gateway-bearing node must supply a valid existing NetworkManager UUID so the Ouranos saved share can be reused rather than creating another live DHCP profile. This does not by itself remove the saved `/etc/NetworkManager` keyfile or prove NetworkManager deduplicates the eventual `/run` keyfile. That exact one-profile migration needs a checkpointed deployment step.

The generated profile pins the declared USB interface and MAC, selects `ipv4.method=shared` with the host CIDR, has autoconnect priority 200 and never becomes the default route. Pinned NetworkManager `firewall-backend=none` leaves DHCP/DNS with NetworkManager while NixOS owns firewall/NAT. Explicit idempotent input, forward, reverse established-flow, isolation-drop and NAT rules restrict forwarding to the declared USB/uplink pair. They do not change the currently running Ouranos operational bridge. The source rejects a second *declared* shared profile, but saved profiles and other runtime firewall owners still need fresh pre-activation inspection.

Focused check `checks/usb-ipv4-gateway/default.nix` evaluates the serializer fixture, the existing kind form, absence on unrelated nodes, duplicate/invalid payloads, missing local UUID, and NetworkManager/networkd/NAT ownership conflicts.
