# Lean interflow messaging correction

Observed 2026-09-21 during Field Astra refresh. The living reported expensive acknowledgment/status messages carrying long hashes. The exact unwanted incoming message was not uniquely identified from this audit, so attribution remains bounded.

The current machine bridge does not itself append full hashes to conversational payloads. `tools/msg` takes one recipient and forwards the supplied body; `tools/messaging.py::make_machine` wraps it in `MACHINE.Relay` with a one-element recipient vector. Its SHA-256 ledger fingerprint is local state, not part of the relay quote. `tools/native-seat-launch.mjs::buildPlan` computes source/profile/prompt digests in plan and receipt fields, while the first native prompt interpolates source paths and bodies, not those digests. Exact API verification still requires complete values in machine receipts. None of these paths should silently truncate an exact-value operation.

`tools/field-refresh-control.py::probe_envelope` builds a one-recipient `Probe` with an `Ack` instruction. The launch worker reported exactly five HM sends: one bare Astra probe, one typed Probe to each Astra and Sol, and one useful Offer to each. The typed Probe/Ack and Offer/Accept replies were observed. Those payloads carried no full UUID or 40/64-character digest; one marker used an eight-character native prefix. This launch testing incurred avoidable extra target turns, but does not explain the full hashes the living saw. Separately, the main flow witnessed Field Sol `7091ea` direct checkpoint/status updates containing full 40-character VCS revisions; no formatter path was established as their cause, and the specific unwanted message remains uncertain.

Authored `behavior` now gives the passive-first/no-status-wake rule. Authored `testing-datom-messaging` directs main flows to keep full digests, UUIDs, and revisions in machine receipts, using only the shortest needed references in conversational prompts and acknowledgments; it also prohibits broadcast route tests and extra echo rounds. This is behavioral guidance, not a parser guarantee. An attempted generic `tools/msg` hash guard was discarded before commit because opaque typed payloads can legitimately carry exact values and the bridge lacks recipient-semantic knowledge. The Mind Message/Flow schema owner must define bounded explicit recipient sets and a test-target policy in the typed contract; that work is not implemented here. No production flow was prompted to test this guidance.

The normal local `curriculum-deploy` generator produced `Generated.{ 65 21 }` and a subsequent `Check.{ 65 21 }` verified current Codex and Claude skill projections. This proves source-to-catalog wiring, not that a model obeyed the new guidance; no paid model turn was spent solely to test wording.

The current Field Astra successor can consume this report as one work amendment with no acknowledgment request. Future route proof should use passive state, local codec tests or a disposable target, and a real authorized work reply when a production recipient is contacted. Raw historical messages and living quotes are preserved.
