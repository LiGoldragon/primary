# Passive Field census restoration

Observed 2026-09-21, Field `6db4fe`. Orchestrate reservations #4142 and #4150 covered the source, installed user-unit links, roster, and this report. This was an observation repair only: no Flow was woken, launched, routed, retired, or reaped.

## Cause and boundary

`tools/field-census/field-census.timer` existed in source, while `~/.config/systemd/user/field-census.timer` and its `timers.target.wants` link were absent. `systemctl --user` reported timer `LoadState=not-found` and inactive; `field-census.service` remained linked and loaded. The journal shows five-minute successful runs through 07:11:49 CST, then a 07:13:40 CST daemon reload and `field-census.timer: Unit to trigger vanished`. The journal identifies the disappearance, **not the actor or reason the link was removed**. A manual service run at 09:05:39 CST left `~/.local/state/field-census/latest.json` at 15:05:39Z. The separate shadow checkup timer still ran, but its service has only `After=field-census.service`; that ordering does not start census. Its 19:35Z assessment therefore read the stale snapshot and marked freshness false. The existing core timers were present but did not replace this sampler; their wake/repair policies remained disabled.

The old `field-census-cycle.mjs` was unsuitable for direct timer restoration: without a flag, it invokes `hm-send` to Field Low and Ultra Low on a 30-minute cadence. Source commits `2bac0ecc3` and corrective `f26ac801e` added `--observe-only`, pointed the existing service at that flag, and documented the passive mode. The corrective commit kept the original HM send block verbatim for manual legacy invocation. In observe-only mode the cycle writes the atomic snapshot before returning, reads no recipient config or notification state, and sends no message. A focused test set a due notification, installed an `hm-send` trap, and confirmed the trap was not run, snapshot refreshed, notification-state bytes unchanged, and cycle lock removed. Eleven relevant Node tests passed. Both source commits were pushed on primary `main`; the exact four committed source files were materialized into the lagging primary working checkout under lock, with prior bytes backed up at `~/.local/state/field-census/rollback-before-2bac0ecc3/`. This is a byte-verified deployment of committed source, **not a claim that the shared JJ working tree is clean or rebased**.
