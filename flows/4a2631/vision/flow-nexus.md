"This is okay but what I have in mind is that people would define how they want to see their thinking machine organized in datom, kind of like how Nix is used to define an operating system.

In this longer-term vision the metaflow becomes not just one main flow, possibly, but it's essentially an entity from the point of view of the metaflow level.
A metaflow talks to a metaflow, potentially through its speaker or whatever its messenger is. Essentially this would be up to the user to define entirely: what that metaflow is, how it's composed, what role the facilities that each part has essentially play, how they connect to each other, and obviously what each harness has in terms of tools and what it doesn't have. That is kind of how I am already envisioning it.
We'll have to get into a lot more detail but that should give you enough direction to redirect this better because as is this is too much hard-coded. I'm not deciding what the particular setup is. I'm going to define how I want my own system to be but another user might have a different setup, different relationships in the metaflow, and different relationships between them."
