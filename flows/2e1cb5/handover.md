## CriomOS, from first principles

My first proposal, the nine families of machinery, he rejected: «it's a mess. You just tried to blend everything together so I guess we'll have to start from first principles, right? What is CriomOS and then what is a Nexus». On the Nexus: «it says Nexus is a System D unit but who's to say that? Maybe somebody wants to use a Nexus that started in another way so that the architecture on the Nexus doesn't bear on whether or not it's started by System D or some other service manager.» On CriomOS: «It's a Nix OS derivative that has a very distinctive way: it reuses an abstraction that Nix OS creates but it doesn't use the same interfaces to build». What he wants to see: «What is CriomOS? How does it relate to lojix, to the horizon, which is from the cluster data, and what are the guiding principles of how we write its code? That's what I want to see, not a bunch of opinions and specifics.» «Let's not base ourselves too much on what the code is because I neglected it and I let the machine operate it for a long time now without almost any supervision.» On AGENTS.md: «I'd like to remove the agents.md so potentially this could become a knowledge module. I know the knowledge module is going to be full of stuff that might help you to operate CrioOS but that will essentially incentivize a bad design pattern». He asked for research on «good Nix language design principles and patterns and maybe even libraries». The reading found CriomOS builds through NixOS's own nixosSystem as one nixosConfigurations.target, with the host entering as four overridden inputs; when I wrote «nothing of NixOS's hosts» he asked «What do you mean by NixOS's host?» and then «Oh you were talking about the flake standard, right?» Proposal: What CriomOS is.

## Lojix and evaluation

He asked «Would there be an advantage to adapting to» the per-host flake standard, then «Would it evaluate faster after caching?», then gave the shape himself: «We create a fixed derivation, right, with a known output, a known hash», «it's just one entry point, which is the fixed-output derivation, which creates the CLI call, which Nix can then cache because it knows, "Oh yeah this is a pure input"», «If nothing changes the program that generates this gets the same output, which creates the same call for Nix, and then Nix's cache kicks in.» On modularizing: «You have next packages pre-evaluated and then you use those packages as an input to another entry point.» And the set: «A declared package set includes all the packages that we might need, whether or not they're used, pre-evaluated. This includes anything that might go into the Nix evaluation, which is the expensive one that does the operating system modules with the cluster data. All of the packages that it uses in its code come from this attribute set of known output packages of content-addressed packages so it's not per host.» The word he reached for: «What is this intentional store?», the intensional store of Dolstra's thesis. Then the brake: «now we're kind of going far with this. This could be like a new rewrite of logics I guess but maybe it'll help you to see where I'm trying to go with this.» Not in any proposal yet; it goes in a Lojix version module after the version ruling.

## Sema: the document, and the shapes of expression

«This could be like the first prototype of SEMA actually. What if we take the things that Markdown can do and then we specify that in a sane manner? We don't need to say title, subheading, and sub-subheading. We can be more thoughtful than that.» «You should do an anatomy of grammar, expression, and language, and have variants so that we can have typed content.» «And create a spec that allows for recursion where recursion would be appropriate.» When I wrote the full clause grammar: «you went way too far. Be practical. Yeah we're gonna get somewhere that looks kind of like what you're showing me but you went too far too fast.» Then the shape of version 1: «When you go that far you would have way more top-level variants so you wouldn't have to be so verbose about its content. Instead of saying "substance, substance, and all that," you would have a variant that is for that very combination of statements. You would just have a pretty long list of different types of expressions. You're welcome to give it another shot but as a separate, let's call it, version 1. This would be version 0.» On addressing a block, in order: positional path, «I'm having a hard time understanding this»; content link, «No content addressing is madness at this point»; then «position is not important. What matters is what it is a child of so it's by naming the sections.» «Changing the meaning means changing the names of its parent sections, right? Then you'd have an operation to get the tree of the section names.» Proposal: The document: Sema version 0 and version 1, with Place and Outline.
