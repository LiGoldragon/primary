# Kameo fork/upstream connection and alignment map

Observed 2026-08-22. This is a sourced comparison of causal guarantees and design alignment. It is not a migration verdict.

## Boundary and status

The fork is `LiGoldragon/kameo` `main` at `3486e4f`; upstream is `tqwewe/kameo` `origin/main` at `b4aaee7`; their merge base is `4d2e2d0` (2026-06-19). The fork’s lifecycle work is in five commits from 2026-05-16 and a rebase adaptation on 2026-06-19. The latest upstream release is `v0.22.2` (2026-07-17 changelog / 2026-07-18 tag); `origin/main` is newer and includes merged-but-unreleased macro `syn` 3.0.2 source changes. Open PRs and branch tips below are explicitly not release or `main` guarantees.

Status terms in the matrix:

- **Released/current** means in a release or in fetched upstream `origin/main`.
- **Merged-unreleased** means on `origin/main` after the latest release but not tagged.
- **Proposed** means an open PR/branch, with no behavior authority.
- **Unknown** means a commit/claim cannot be established from the effective source, even if its title suggests it.

## Causal connection matrix

| Fork guarantee or mechanism | Upstream released/current shape | Classification | Causal explanation and open direction |
|---|---|---|---|
| **Terminal outcome cell.** A shared `SetOnce<ActorTerminalOutcome>` reports state absence (`Dropped` or `NeverAllocated`) and terminal reason. The fork’s `wait_for_shutdown` resolves only after cleanup, actor-state drop, link notification, unregister, and compatibility result publication. | **Partial terminal results.** Upstream has startup/shutdown result cells and waiters, but no terminal outcome/state-absence type. Its `wait_for_shutdown` observes mailbox closure; current lifecycle orders link notification before `on_stop` and does not make post-drop outcome publication the public boundary. | **Partial overlap** | Both expose eventual startup/shutdown observations. They differ on what the observation proves: upstream result means hook/result processing completed, while the fork’s outcome additionally claims the actor state is gone and notifications have happened. PR [#394](https://github.com/tqwewe/kameo/pull/394) (“release terminal child ownership”) is a **proposed** direction that may overlap the ownership half; it is not equivalent until merged and specified. The fork’s public `Ejected` state variant has no observed constructor/use, so that taxonomy remains partly undesigned in the fork itself. |
| **Separate lifecycle/control lane.** Stop, startup, and link signals use an unbounded control lane independent of bounded user-message capacity. | **One channel plus an admission flag.** `stop_gracefully` flips admission closed before sending `Signal::Stop`, but lifecycle signals share the ordinary channel. | **Partial overlap** | Admission closure addresses the same “new user work after stop” race. It does not provide control priority: a bounded control send can wait behind capacity, whereas the fork’s control lane can arrive while the ordinary lane is full. No current upstream change establishes the fork’s two-lane mechanism. |
| **Stop wins over queued ordinary work.** The fork allows the in-flight handler to finish, then control processing discards ordinary queued messages; tests require no queued `UserWork` to run after stop control wins. | **Graceful stop processes already queued work.** Current docs say stop occurs “after processing all messages currently in its mailbox”; newly sent messages are rejected, but pre-existing queued messages are not discarded by stop admission. | **Conflicting** | This is an observable ordering/retention contract, not an internal refactor. The fork prioritizes the control lane and drops queued ordinary messages; upstream’s one-lane FIFO shape lets queued work precede `Signal::Stop` and be processed. The upstream change [e8a0bce](https://github.com/tqwewe/kameo/commit/e8a0bce041af295eb3c013be08b5282fda4d9b7b) is the release-era admission change, not the fork policy. |
| **Admission generation gate.** A pending bounded send rechecks the generation after waiting for capacity; a send that began before stop cannot cross the closed-admission boundary and succeed later. | **Admission check before channel send.** Current sender checks the flag before awaiting bounded capacity; the source does not perform the fork’s post-wait generation recheck. | **Partial overlap** (with a conflicting edge case) | Both reject ordinary sends after stop begins in the uncontended case. Under bounded contention, the fork prevents a pending send from becoming successful after closure; current upstream can retain a sender already inside `send` and potentially admit it when capacity opens. The exact pending-send outcome is therefore not equivalent. |
| **Teardown drains while children close, then publishes outcome and notifies with that outcome.** Link/supervisor callbacks receive `ActorTerminalOutcome`; replacement tests require prior state drop before new start. | **Teardown drains while children close, then notifies with stop reason and mailbox ownership before `on_stop`/actor return.** Current supervision preserves tells for a predicted restart and can notify the parent before state drop. | **Partial overlap** for drain/waiting; **conflicting** for ownership/order | Both prevent child-channel deadlock and coordinate children. The fork makes “drop before notification/replacement” causal; upstream’s notification-before-drop path leaves a window for early replacement and does not carry state absence. Open [#387](https://github.com/tqwewe/kameo/pull/387) (serialize supervised restarts) and [#394](https://github.com/tqwewe/kameo/pull/394) are **proposed** overlap, not current equivalence. |
| **Weak shutdown helpers gated by terminal cell.** `WeakActorRef::get_shutdown_result` and closure helpers remain `None` until terminal publication, even after `on_stop` has completed. | **Weak helpers gated by compatibility shutdown result.** Current accessors become available after `shutdown_result` is set, before the fork’s post-drop/post-notification point. | **Partial overlap** | Both avoid exposing a running actor as stopped. The fork closes the visibility window more strictly; upstream has no terminal cell to make the same claim. This is compatible only if downstream needs the weaker upstream meaning “shutdown hook result exists,” not the fork’s stronger meaning “terminal resource lifecycle is complete.” |
| **Queued asks under fork stop.** Lifecycle test expects a queued ask discarded by stop to report `SendError::ActorStopped`; teardown discards signals while waiting for children. | **Request/reply accounting.** During drain, asks are bounced with the original message as `ActorRestarting` if restart is predicted or `ActorNotRunning` if terminal; terminal leftover asks are not silently dropped. | **Conflicting** | The error value and retry causal path differ. Upstream gives the caller a classification and original message for retry/accounting; the fork’s observed stop test expects `ActorStopped` and its teardown does not implement that bounce policy. This is a breaking API boundary in upstream `0.22.0`, not an implementation detail. |
| **Queued tells are discarded by fork teardown/stop.** No fork `on_undelivered` path was observed in the lifecycle branch. | **Terminal tells are collected for `Actor::on_undelivered`; restart tells are preserved and requeued.** | **Conflicting** | One shape intentionally loses queued tells at stop/restart boundaries; the other preserves or surfaces them. Upstream’s `on_undelivered` behavior arrived in `0.22.0` and is released. Any shared caller contract must choose one delivery/accounting rule. |
| **Supervision uses the fork’s terminal reason/outcome to decide restart and to coordinate resource release.** | **Supervision policies/strategies are released: `Permanent`/`Transient`/`Never`, `OneForOne`/`OneForAll`/`RestForOne`, with a five-restarts-in-five-seconds default budget and shared restart-intensity prediction during drain. | **Partial overlap** | Both have parent/child supervision, restart policy, and restart-budget concerns. The fork changes the evidence used at the decision boundary and the ownership order; upstream’s richer drain classification is not present in the fork. Open restart-serialization work may converge some timing, but the exact policy contract remains unsettled. |
| **Fork `PreparedActor::run` no longer returns actor state**, so lifecycle code drops it before terminal publication/restart notification. | **Current `PreparedActor::run` returns `(A, ActorStopReason)`**, retaining actor state in the task result until that result is consumed/dropped. | **Conflicting** for the resource-release guarantee | The return type determines who can retain the actor state and when `Drop` is observable. The fork’s change is a causal ownership mechanism; upstream’s return shape cannot prove the fork’s post-drop boundary. |
| **Lifecycle tests use external resource/drop probes, oneshot witnesses, bounded-mailbox pressure, and supervision restart observations.** | **Upstream also has behavior tests for mailbox preservation, deadlock prevention, send errors, supervision, and `on_undelivered`; its release notes call out CI/test reliability.** | **Complementary**, with a testing-rule caveat | Both test actor machinery through observable behavior rather than source-text searches. The fork’s `sleep`-based pressure checks and timeout windows are useful race witnesses but clash with the authored rule to await the tested event rather than a clock; oneshot/drop probes align. Upstream’s drain tests cover behaviors absent from the fork. |
| **Fork’s current remote implementation is inherited libp2p-era Kameo remote behavior, with terminal outcome additions for peer disconnect.** | **Released/current remote remains libp2p transport + Kademlia provider registry + request-response and composable behavior.** | **Equivalent** at the broad transport shape; **partial overlap** at API/version detail | Both retain the same broad distributed-actor architecture at the comparison boundary. This does not establish that fork and upstream wire/API details remain compatible; the fork is on an unreleased `0.20.0` manifest while upstream is `0.22.x`. |
| **Fork has no shipped chitchat/TCP/MessagePack remote redesign.** | **`kameo_remote`, core-remote removal, TLS/cluster-key auth, serialized restarts, terminal ownership, and non-`'static` message work are open branches/PRs.** | **Orthogonal** to current fork guarantee; **proposed/conflicting** if adopted as transport contract | These proposals are upstream direction signals, not current behavior. The separate remote crate could complement actor-core use, but it would replace rather than refine the fork’s current libp2p wire shape. TLS without the proposed cluster key does not authenticate gossip, per the proposal’s own warning. |
| **Fork remains on the pre-console/pre-0.21 API and 0.20.0 manifest.** | **Upstream has console TUI, ask reply defaults, `pipe`/`pipe_with`, `on_undelivered`, `SendError` changes, hotpath/tracing fixes, release-plz, and MSRV/edition/package updates.** | **Orthogonal** to fork lifecycle guarantees; **complementary** as maintenance/observability | These changes affect ergonomics, observability, and compatibility rather than proving or disproving terminal lifecycle semantics. Console can be a debugging/client surface around actors; it is not the Nexus signal contract. Open release candidate [#386](https://github.com/tqwewe/kameo/pull/386) remains **proposed**. |

## Alignment with written psyche and authored designs

| Concern | Fork shape | Upstream shape | Design reading |
|---|---|---|---|
| **Kameo’s role** | Actor runtime and a forked actor library. | Same actor-runtime family with active lifecycle, supervision, remote, console, and macro work. | **Aligns only at the selected layer.** The current actor-library record says Kameo is intended as the Nexus actor layer but that standards of use have not been designed. The same record says to distrust prior work, including the fork. Neither implementation is authority for those standards. |
| **Lifecycle contract** | Public terminal outcome, phase-like admission/termination distinction, post-drop notification. | Public shutdown result, drain/restart/undelivered contracts, no terminal outcome type. | **Undesigned at psyche level; implementation at code level.** No read psyche source chooses stop ordering, terminal taxonomy, queue retention, or restart ownership. The fork’s stronger outcome is not automatically more aligned merely because it is more explicit. |
| **Traits as comprehension surface** | Public lifecycle methods are mostly inherent methods on `ActorRef`/`WeakActorRef`; internal handler traits exist. | Same general pattern: `Actor`, `Message`, `Reply`, handler traits, plus many inherent ref methods. | **Strictly clashes with the authored mandatory-traits rule as source shape; semantically useful traits are partial alignment.** The authored rule says every Rust method call is under a trait and types/traits are designed before bodies. This comparison cannot infer the eventual Nexus trait ontology from either implementation. |
| **Nexus boundary** | Kameo local messages are typed actor calls; fork remote remains a libp2p actor transport. | Same released remote family; proposed redesign uses TCP/MessagePack. | **Internal actor layer can be complementary; direct transport substitution clashes with authored Nexus boundary.** Nexus requires at least two sockets/clients and a pure typed binary `Signal`, with peers depending on wire-type repositories rather than daemons. Neither current Kameo remote shape is evidence that it is the Nexus wire contract. A future adapter may be possible, but that adapter/ontology is undesigned. |
| **Supervision and dataflow** | Parent/child links and restart coordination, with extra terminal ownership evidence. | Parent/child links, policies/strategies, restart budget, drain preservation and ask classification. | **Candidate implementation, not settled ontology.** Both could inform an actor/dataflow map; exact restart and delivery semantics remain open. Do not attribute a desired failure model to the psyche from either branch. |
| **Testing design** | External resource/drop and channel witnesses are good evidence; clock sleeps/timeouts are used for some pressure/race checks. | Behavior tests cover lifecycle/drain/mailbox/supervision; current source also uses timeout-style race protection. | **Mostly aligns in method, partial clash in timing technique.** Tests observe the machinery and use values/probes outside the actor under test; source-text pinning was not observed. The authored testing rule requires waiting on the tested event rather than a clock, so pressure tests should remain clearly labeled as race witnesses rather than normative timing contracts. |
| **Spirit/authority discipline** | Fork history is a prior implementation with no current psyche design authority. | Upstream releases, merged code, and open proposals have different authority levels. | **Process alignment requires explicit status separation.** Spirit gives no Kameo-specific lifecycle choice; it requires claims to be grounded and unresolved intent returned. Released, merged-unreleased, proposed, and unknown work must not be collapsed. |
| **Toolchain and maintenance** | 0.20.0 manifest and no console workspace member at fork head. | Edition 2024/MSRV 1.88 core, macro MSRV 1.85.1, four workspace packages, release automation, active PRs. | **Implementation/maintenance signal, not ontology.** It changes compatibility and operational cost but does not settle actor standards, trait map, or Nexus wire shape. |

## Most illuminating visual structure

The clearest companion to this matrix is a **two-lane causal lifecycle sequence diagram**, not a migration tree:

```text
stop request
    │
    ├─ fork: close ordinary admission ──┬─ control lane wins
    │                                   └─ in-flight finishes → queued ordinary work discarded
    │                                      → drop actor → notify(outcome) → publish terminal outcome
    │
    └─ upstream: close admission ──────┬─ one FIFO channel
                                        └─ queued work drains → preserve tells / bounce asks
                                           → on_undelivered on terminal stop → notify(reason)

                    shared downstream question: what does “shutdown observed” prove?
```

Add a narrow side band at the bottom for the Nexus boundary: `typed local actor message` → `future Nexus Signal / socket contract (undesignated)`. Mark open upstream PRs as dashed nodes after, rather than merging them into either lane. This makes the true conflicts—stop ordering, queued message accounting, and resource-ownership visibility—visible without implying a migration choice.

## Unresolved questions returned to the caller

- Is terminal lifecycle outcome (including state absence and notification ordering) a desired actor-library contract, or only a fork implementation experiment?
- Which queued-message policy is wanted: fork control priority/discard, upstream process/preserve/report, or a new policy designed from the Nexus actor ontology?
- Should lifecycle observations and all actor-ref operations be redesigned under the mandatory trait map before implementation is considered?
- Where does Kameo stop and the Nexus typed-binary signal/socket boundary begin? The current remote implementations do not answer this.
- Should testing witnesses eliminate clock sleeps/timeouts in favor of tested-event coordination, and which race probes are genuinely contract-bearing?
- Which upstream status is authoritative for any later work: released `v0.22.2`, merged-unreleased `origin/main`, or a separately reviewed proposal? No choice is made here.
