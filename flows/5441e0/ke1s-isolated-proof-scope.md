Keep both production Flow endpoint declarations and both live Codex servers untouched. Use a separately declared disposable Flow Nexus/place with fresh Memory, its own ordinary/meta sockets, clients bound to that place, and a separate Herdr test session/workspace. Its two-slot contract is unchanged: the new disposable Codex server occupies one otherwise empty slot of this independent proof Nexus. Thus three servers coexist on the host while no production slot is replaced. This is an isolated-proof proposal for Core/Field review, not a claim that the place already exists or permission to start it by hand.

Exact serving Flow52e already declares Terra in flow-ethos/ethos/library.ethos13. codex.rs94–152 selects an endpoint by an exact configured native model string; the configured endpoint carries client path/socket/home, and separate stable/next model lists must not overlap. No alias to Sol or another model is acceptable.

## One-launch/one-Send/one-resume acceptance contract

1. Record metadata-only baselines for BOTH live server routes/PIDs/socket/state identities and the proof declaration; no production query changes state.
2. Through the isolated proof Flow client, Rehearse and then Start ONE cheap disposable Terra flow at the exact configured native model/effort. Verify actual native launch receipt, selected model/endpoint, native thread and first response. This must exercise Flow's dynamic-tool launch gating; permission prompts/refusal/timeouts are failures, not success by pane existence.
3. At that throwaway's actual rest, use the proof meta client's supported `Restart.<FlowId>` (meta83 signal.ethos333), not Refresh. Require old harness closure, supported resume, same native session/thread and binding identity, and actual resumed response. The command's success alone is not proof of model continuity.
4. Use ONE ordinary `Send` through the proof Flow client to the throwaway and require the actual native prompt/response acknowledging its unique marker. Admission/submission/Uncertain is not a read receipt. Performing this after Restart can establish resumed message service with only one Send. This proves ordinary delivery; it does not independently prove a native dynamic Send-tool call. If the intended ruling requires a model-originated Send-tool invocation instead, agree that exact variant before launch; do not silently substitute one proof for the other.
5. Record exact failures and boundaries. Stop ONLY the disposable flow; require supported final state/pane closure. Field tears down only the declared proof Flow/native server/session/socket/state and removes its declaration through the approved path. Compare BOTH production routes/PIDs/identities against the baseline. Never archive a production thread, retarget either live route, overwrite a live HOME, or treat an old gate as candidate compatibility proof.
