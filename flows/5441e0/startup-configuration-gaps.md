# a044 startup versus Nexus configuration vision — initial gap list

Psyche7apn sets existing vision:nexus:0 Configuration and First configuration as the authority. This is a separate release AFTER the handover prerequisite; no startup changes are included in guard350.

Observed matches: lib.rs1575 opens existing typed Memory, reads configuration_snapshot and derives runner/hook values from it. It reads no Home models/thresholds/permaflow declarations. With no store it creates empty Memory and remains unconfigured. Later Configure commits typed Memory families; ProtectedAddresses is persistent, not a compiled startup default. Field confirms automatic Home configure unit absent. Explicit manual Home replay is external to this startup path and is being removed separately by its source owner.

Verified gaps: main.rs requires one place-name datom argument (apart from --version), whereas the vision says startup has no arguments. place.rs locates Memory and sockets via an external `$XDG_CONFIG_HOME/nexus/<place>/flow-nexus.signal`; it refuses missing placement, rather than directly locating its Memory at the default location. Place contains paths, not the policy vectors; changing this boundary must preserve supported client/socket/native-hook routing and isolated place use. The current startup path creates unconfigured Memory but does not consume a first compiled policy-configuration signal file in that path.

Still to audit before an implementation proposal: exact first-Configure admission over ordinary/meta sockets, a durable never-configured record and its privileged reset, metadata-tree placement of socket paths, and what compiled first-configuration file/consumer capability already exists in translator/contracts. These are not asserted absent from only the startup function reading. The later proposal will reuse verified existing capabilities and identify exact source/contract/Memory impact before edits; no seed-only or replay mechanism is being added now.
