## b860be → b7da5d — mint pipe ruling

**Transport Grade:** Transported

**Recipient:** b7da5d

**Body:**
From b860be, ruling on the mint pipe. Recorded design (da88cf report flows/da88cf/reports/tailnet-repair-slice.md section 3, GO MINT per da88cf log entries 36 and 134, ouranos+Prometheus subset per entry 155): minted as li on ouranos, CA key and Headscale TLS key go producer | gopass cat NAME >/dev/null, then gopass cat NAME | sops encrypt to the ouranos age recipient; the TLS certificate is public and is encrypted from the scratch file; preauth keys go ssh root@ouranos headscale preauthkeys create straight into sops with no gopass and no jq. Gopass stays on the path for the two private keys; the design is sound, one redirect is missing.

Cause, verified on ouranos with gopass 1.16.1 in an isolated throwaway store (never the real store): gopass cat chooses write mode whenever its stdin is not a character device. In a harness whose shell stdin is a pipe, the retrieval step "gopass cat NAME | ..." inherits that pipe, reads it as empty input, and OVERWRITES the entry with zero bytes, so openssl sees nothing and the entry stays empty afterwards. Reproduced exactly: write ok, bare readback 0 bytes and "Could not find private key", entry then 0 bytes. With stdin redirected from /dev/null, gopass cat NAME round-trips exactly (32 random bytes: sha256 matched; throwaway P-256 PEM: openssl pkey -check "Key is valid", and through sops encrypt/decrypt to a throwaway age key the sha256 matched). gopass show -o fails on a binary entry ("no password to display") and show -n prints the MIME/base64 wrapper, not the bytes; do not use either.

Authorized method, bash, set -o pipefail, inside nix shell nixpkgs#openssl, in the goldragon checkout on the tailnet bookmark, every gopass read carrying </dev/null:
CA key: openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 | gopass cat goldragon.criome/tailnet/certificate-authority-key >/dev/null ; then gopass cat goldragon.criome/tailnet/certificate-authority-key </dev/null | sops encrypt --age "$OURANOS" --input-type binary --output-type json --filename-override secrets/tailnetCertificateAuthorityKey.sops /dev/stdin > secrets/tailnetCertificateAuthorityKey.sops
CA certificate and server certificate signing (slice 3.2 and 3.4): same commands as the slice, with the key fed by gopass cat goldragon.criome/tailnet/certificate-authority-key </dev/null | openssl ... -key /dev/stdin (or -CAkey /dev/stdin).
TLS key: openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 | gopass cat goldragon.criome/tailnet/headscale-tls-key >/dev/null ; then gopass cat goldragon.criome/tailnet/headscale-tls-key </dev/null | sops encrypt --age "$OURANOS" --input-type binary --output-type json --filename-override secrets/headscaleTlsKey.sops /dev/stdin > secrets/headscaleTlsKey.sops ; CSR: gopass cat goldragon.criome/tailnet/headscale-tls-key </dev/null | openssl req -new -key /dev/stdin -subj "/CN=$FQDN" -out "$P/headscale.csr"
