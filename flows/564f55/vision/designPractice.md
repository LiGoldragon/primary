# design practice

## 2026-09-08 — machines think in code; talk to a machine about code with the code, so the next machine reading it understands

Answering a distillation proposal that described inline type declaration in prose, without code:

> When you say a type, maybe declare where it is used. You talk about inline type declaration, but you're not even giving me any example code, which is kind of absurd. Machines think in code, and I don't know why you would talk to a machine about code without giving him the code. Why don't you just redo all of that with some example code for everything, so that at least I can see you understand, and then we can expect the next machine to read this to actually understand?

-- psyche, STT.

## 2026-09-08 — example code is for what the models don't know: ethos, datom, what ethos turns into in Rust, datom in Rust; not Cargo files

Answering the redone proposal, which had shown a Cargo dependency line as example code:

> Okay, now let's look at a thorough vision distillation with example code, but I don't need example code for stuff like how to define a dependency in a Cargo configuration file. That's ridiculous. This is the kind of stuff that the models already know. Just saying that the crate is called datom-codec is enough for them to understand how to do this.
>
> The code they don't know is Ethos and datom, what this Ethos should turn into in Rust, and how to use datom in Rust.

-- psyche, STT.
