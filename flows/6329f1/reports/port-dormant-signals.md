All three repositories use `.schema` files and `schema-rust` as a build
dependency. None has `.ethos` files. Per the brief's classification:
a `.schema` generated by schema-rust is the frozen earlier lineage.

## meta-signal-upgrade

**What it is**: Meta-policy signal contract for the `upgrade` triad.
Carries catalogue-policy authority and selector authority. Generated
from `schema/lib.schema` by `schema-rust`.

**Lineage**: schema-rust (`.schema` files, `schema-rust` + old `protos`
build deps). The committed build.rs calls `schema_rust::build::ContractCrateBuild`
with `WireContractFamily::MetaSignalSpirit`.

**Old API surface**: protos (build-only: `WireContractFamily`), schema-rust
(build-only: `ContractCrateBuild`), signal-frame, dotos (optional text codec),
rkyv. No ethos-zero or datomic dependency.

**Dirty attempt**: 2371-line uncommitted diff saved as
`reports/meta-signal-upgrade-dirty.patch`. The attempt modernized
nota to dotos, branches to pinned revs, and added `links`/`build`
fields. It did NOT attempt a port to the ethos lineage: the build
still calls schema-rust, the `.schema` files are unchanged, and
the protos rev pinned is still 9bce5ed8 (pre-train). This attempt
is **superseded** by the broader rewrite approach of this flow.

**Consuming nexus**: `upgrade` (Active). The upgrade nexus still uses
nota (not dotos), branch-tracking deps (not pinned revs), and
schema/schema-rust build dependencies. It pins meta-signal-upgrade
and signal-upgrade by `branch = "main"`.

## signal-terminal

**What it is**: Signal contract for Persona terminal transport control.
Owns typed request/event vocabulary for terminal connection, input,
resize, capture, prompt patterns, input gate leases, injection,
worker lifecycle, and session lookup. Generated from `schema/lib.schema`
by `schema-rust`. Has hand-written convenience impls in `src/lib.rs`
(payload accessors, operation_kind dispatch, rkyv serialization) and
an `introspection` module.

**Lineage**: schema-rust (`.schema` files, `schema-rust` + `schema` +
old `protos` build deps). The build.rs calls
`schema_rust::build::ContractCrateBuild` with
`WireContractFamily::SignalSpirit`. Also depends on `schema` (the
older schema crate) as a build dependency.

**Old API surface**: protos (build-only: `WireContractFamily`), schema
(build-only), schema-rust (build-only: `ContractCrateBuild`),
signal-frame, dotos (optional text codec), rkyv, thiserror.
No ethos-zero or datomic dependency.

**Consuming nexus**: `terminal` (Active). The terminal nexus already
uses dotos (not nota) and pinned revs. It pins signal-terminal at
rev c247cbfe and meta-signal-terminal at rev 3a5f26f9. The terminal
nexus also uses schema-rust as a build dependency.

**Psyche**: no psyche record found naming signal-terminal.

## What it would take to port each

Porting these from schema-rust to the ethos lineage (following the
signal-orchestrate pattern) would require for each:

1. Write an `ethos/signal.ethos` in the Signal anatomy (aliases,
   no single-field structs, Channel gone, wire version from the
   Signal's version).
2. Replace build.rs to call ethos-zero (or ethos-monolith) instead
   of schema-rust.
3. Replace `schema-rust`, `schema`, and old `protos` build-deps with
   ethos-zero/ethos-monolith and train-rev protos/datomic.
4. Regenerate `src/generated/signal.rs`.
5. Update the hand-written codec/convenience code (signal-terminal
   has substantial hand-written impls).
6. Update the consuming nexus to use the new generated types.

For **meta-signal-upgrade** and **signal-upgrade**: the upgrade nexus
itself is still on the old nota/branch-tracking lineage and would
need to be ported first or simultaneously. The nexus has not been
modernized to dotos yet.

For **signal-terminal**: the terminal nexus is already on dotos/pinned
revs but still on schema-rust. It would need its build pipeline
updated to match.
