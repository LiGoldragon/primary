## Judgment calls (this subflow's, flow 6329f1)

1. **LockId removed from ethos**: ethos-zero c85e9f76 generates `LockId.Integer` as a single-field struct (not a type alias) in Signal mode because aliases cannot carry rkyv derives. This conflicts with `Release.42` (bare integer) canonical form and the "no single-field structs" rule. Resolution: removed `LockId` from the types section; `Release.Integer` and `Lock.{ Integer ... }` use Integer directly. The type alias is gone.

2. **ethos-zero Corporal/Datomic split defect**: ethos-zero c85e9f76 generates `impl datomic::Datomic for T { fn incorporate(...) fn datomize(...) }` but datomic 768426ea moved `incorporate` to `protos::Corporal<Datom>`. A Python script mechanically splits the generated impls after regeneration. Recorded in api-deviations.md. Not a one-line emitter fix; routed to the coordinator.

3. **Domain rejections in Reply, not Refusal**: The new signal contracts place LockRejected and ReleaseRejected as Reply variants, not Refusal variants. Refusal is wire-level only (VersionMismatch, Unreadable). The orchestrate store and tests were updated accordingly.

4. **Refusal handled via Debug**: The wire Refusal type has no Datomic impl (it is not a domain type). CLIs handle it with Debug format to stderr.

5. **CriomOS-home not merged, not deployed**: Per the brief, the branch is pushed but not merged. The running nexus is the living's to replace.
