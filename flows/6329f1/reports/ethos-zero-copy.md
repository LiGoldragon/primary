# ethos-zero-copy -- derive Copy for unit-only enums

Report for flow 6329f1, carried account.

## Substrate

- ethos-zero 1.2.0 main 8bcb0b94: Library derives Clone/Debug/PartialEq/Eq; recursive positions boxed

## Problem addressed

curriculum-deploy 0.5.0 hand-wrote four `impl Copy` lines for unit-only enums
(Provider, Permission, Effort, Surface) because ethos-zero 1.2.0 did not derive
Copy. The generator already knew from the declaration that all variants carry
nothing; it did not use that information to select Copy.

Deviation 3 from repin2.md: "ethos-zero 1.2.0 Library derives do not include
Copy. The four unit enums... still need Copy impls that the generated code does
not emit."

## Change

**Worktree**: /home/li/wt/github.com/LiGoldragon/ethos-zero/ethos-zero-copy-6329f1
**Orchestrate Lock**: 656

Two helpers added to `src/lib.rs`:

- `fn all_variants_unit(variants: &[Variant]) -> bool` — true when every
  variant is `Variant::Unit`.
- `fn enum_derive(signal: bool, unit_only: bool) -> proc_macro2::TokenStream`
  — returns the correct derive attribute for the combination.

`type_declaration_tokens` (Enum arm): the derive is now computed with
`enum_derive(signal, all_variants_unit(variants))` instead of the fixed
signal/library derive.

`emit_variant_tokens` (InlineEnum arm): the inline enum now uses
`enum_derive(signal, all_variants_unit(inner_variants))` for its inline type.

Signal unit-only enums carry the same `Archive, RkyvSerialize, RkyvDeserialize`
plus `Clone, Copy, Debug, PartialEq, Eq`. The brief says "match, do not invent"
for PartialOrd/Ord/Hash; the prior Signal emission had none of those for
unit-only enums, so none were added.
