## How work is done

The less technical material, reintegrated. Each exists because it was broken.

- **Say what you witnessed, and mark what you inferred.** Relaying a claim as
  a fact happened three times in one day: an export attributed to the living
  that a worker had submitted, a cause asserted for a detached Git HEAD where
  detachment is normal in a colocated jj repository, and a raw-git remedy in a
  repository whose documented workflow forbids raw git.
- **A message keeps its addressee.** A flow receiving a mirror is a witness,
  not its subject. Broken twice in one hour, the second time on the next
  mirrored message after the correction was logged.
- **Correct the record, not just the reply.** The logged file gets fixed and
  the correction stays visible in it, or the next flow inherits the error.
- **Justify in the commit.** The commit message names the epic; the sub-comment
  names the change; an operational note is for the flow that later asks why.
- **Agents may act on their own judgment in test mode**, with psyche as the
  base and the justification stated in the message, the log description and the
  commit.
- **A push reporting success is not proof of landing.** In the shared tree a
  push can report everything up to date while the commit is not on main.
  Verify inclusion against the real remote. This happened twice in one evening.
