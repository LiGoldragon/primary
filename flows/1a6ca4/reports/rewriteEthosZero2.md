## Decisions on flow authority

- Kind names: `Canonicalizable for Text` (the text undergoes it, as Text is Protosizable) and `Generating for File` (the file does it, as protos' Glyphing/Situating name what the bearer yields): -able for a layer transition the bearer undergoes, -ing for a capability whose yield is a product; the vision's own verb is "ethos generates the Rust".
- The import carries the source name: `source:Ethos.Source`, `source:[ Ethos.Source … ]`; the source is any Rust path prefix written verbatim (`protos`, `crate`, `super`, `std::clone`), the emitted name the source's. The Identity example thus reads `std::clone:Clonable.Clone std::marker:Sendable.Send serde:Serializable.Serialize` and emits `A: std::clone::Clone + std::marker::Send, B: serde::Serialize` — fully qualified, per the psyche's "extremely explicit" Rust; the main flow's `rust:` prelude shorthand was not taken because it needs one named source the generator treats specially.
- Inline qualification in a type position, `Structural.protos:Fault`, is a reference with a source: the import form in place; taken because datomic.ethos cannot describe datomic without it.
- Sema is `[ imports ] { record positions } [ types ]`: the record section is a brace because it is a struct body, as the signal's sections are brackets because they are enum bodies; the record type is `Record`, implied as `Request` and `Response` are.
- An association's head is an identity (name and constraints), never a type expression: `Situated<Datomic>.[ Datomic ]` asserts the blanket impl through a generic assertion function; `Vector<Sink>.[ Datomic ]` is a role fault.
- A type declaration may carry constraints (`Situated<Sized>.{ Option<Extent> Sized }`, `Placed<Sized>` fixture): the identity rule applied to types; its datomic machinery adds `+ datomic::Datomic` to each parameter.
- `Sized` is an intrinsic kind (Vision/protos.md: "Sized is the bound borne by every corporate type"); `Self` an intrinsic type; `Box` and `Symbol` are not intrinsics.
- One boxing rule: a position whose type reaches its declaring type through declared types, aliases, Option and Result (not Vector) is boxed as a whole, `Box<Option<Tree>>` rather than `Option<Box<Tree>>`, so the datom machinery never sees a box and `impl_datomic_box!` is not used.
- Derives: `Clone, Debug, PartialEq`, plus `Eq` unless the type reaches `Decimal`, plus `Copy` when every variant is bare; `#![allow(dead_code)]` at the top of every generated module. Not in the vision's Rust; kept from the first pass, with the Eq rule added because `Score.{ Decimal … }` did not compile.
- An inline enum variant `A.[ … ]` declares a nested enum type named `OwnerA`; Rust has no inline enums. The only synthesized name left.
- Generated incorporation is closure-free: nested matches instead of datomic's `map_err(|f| f.prepend(i))`; the fault shape and paths are datomic's exactly.
- Generated Rust is formatted by prettyplease in the library (deterministic, no rustfmt subprocess); generated modules are declared `#[rustfmt::skip]` so `cargo fmt` leaves the product alone.
- Names are validated as Rust identifiers by syn (`Self` allowed); a keyword is a `Name` fault; case is not ruled (`record` reads).
- The reader bounds nesting at 128 with a `Depth` fault found by an iterative survey; protos bounds at 100 000.
- The no-argument CLI prints the sweet file verbatim (its comments included) rather than the canonical one-line form.
- Capability inputs are named `input` for one, `input_0…` for several (unchanged from the first pass).
- protos and datomic patch bumps carry only their .ethos declarations and, for datomic, the pin of protos 0.18.1, so ethos-zero pins one revision per crate in Cargo and in the flake; their Rust is 0.18.0's and 0.12.0's.
- `#![allow(clippy::manual_find, clippy::manual_map)]` in lib.rs: clippy asks for iterator adaptors with closures where the crate walks its enums as loops.

## What depends on datomic's shape (for the third-pass re-pin)

## Left hanging

- protos: the situation map records a headed structure's extent as its head's alone (the head's sub-situation overwrites the whole extent under the same path), and a qualified head's constraints share paths with the headed body (`Processable<[Clonable Sendable] …>.[ … ]`: constraint 0 and the body are both child 0). Witnessed: `Undeclared.Clonable` at the right path but the body's extent. Out of this pass's write set (protos Rust); reported for the third pass.
- datomic: corporate fault paths are relative to the datom root while the delineation situates the root at `[0]`, so `Situated` extents of `Malformed` replies land one level off (`Generate.{ /only }` reports the head's extent). Same disposition.
- Inline enum variants synthesize a type name; no better Rust exists.
- The `Reaching` walk recurses once per declared type on the way to a cycle; a file of thousands of chained declarations would recurse that deep (the reader's depth bound covers nesting, not chains). Inference: harmless at any real size; noted.
- The dependency declarations describe their crates approximately (`Delineation.{ Vector<Protoform> }` omits the situation; `Prepending.[ prepend.{ … } ]` writes `.` for a by-value receiver ethos cannot write; `Pathed` is undeclared). Only validity was fixed, as briefed.
