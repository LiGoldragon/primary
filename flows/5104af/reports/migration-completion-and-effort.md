## Why creation can use fewer model calls

The migration-specific Field adapter does one checksum gate plus one os.execv with a 14-element argv (executable, six flag/value pairs, prompt), not 16. Its meaningful first task also reconciled old context and created acceptance records; that work explains much of this migration's model overhead and is distinct from creation itself.

The completed read-only launch review found: generic standalone creation has a source-supported minimum of 16 direct subprocesses, three request/reply RPCs, one initialized notification and three rollout polling gates. Flow Nexus Start is deterministic controller code: minimum nine controller-spawned subprocesses (ten including caller), seven request/reply RPCs and two notifications, exactly one turn/start invoking the new session, no controller-side judgment call. These are source-supported minimum counts, not measured wall time or prices.

Psyche directs session starts through Flow CLI/Flow Nexus, premade roles and minimal shorthand producers. The new living vision asks for near-zero model calls and, where needed, a tiny judgment analogous to database-fit judging. Plausible design: explicit typed/template request needs zero creation-side model calls; ambiguous natural language needs one small bounded routing judgment, followed by code resolving defaults and doing identity, authorization, launch and registration. The new session's own task turn is counted separately. Judge model/schema and shorthand/profile producer remain design choices; no controller implementation change was made during this migration.
