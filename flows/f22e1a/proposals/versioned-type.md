# An incompatible version is its own type

Created by Fable 5.1, on the living's words.

### Proposal 1: The version in the name · psyche-belief › vision/versioning.md

::: comment
A complete rewrite shares nothing with the version before it, so a value of the one is never a value of the other, and a system may hold both while the earlier converts into the later. :::

+ ## A version that shares nothing is its own type

+ A complete rewrite shares nothing with the version it replaces, so a value of the one is never a value of the other; the two are two types, and a system may hold both while the earlier converts into the later. The type's name carries its version as a word, as Ethos Zero does: `SemaZero` is version 0 of Sema, and the bare name, `Sema`, is the language itself, taken by no version. The manifest versions what stays compatible: revisions and subversions change the number and leave the name.

```ethos
+ ModuleText.SemaZero                ; version 0 of Sema; its successor is another type
```
