# A thing is done once, in one place

Created by Fable 5.1, on the living's words and on the evidence of Psyche core Opus.

### Proposal 1: Once · psyche-belief › spirit/core.md

::: comment
The flow flake check compiles the workspace about 120 times, once per named test, each test already run by the default check; the helper came in two months ago and 153 commits each added a line. No module said that what is done is done once. The ethos vision says it of syntax; it holds of everything, so it is spirit.
:::

+ A thing is done once, in one place: a build, a proof, a computation, a statement. A second place that does the same is the first, split, and the two are made one.

### Proposal 2: A change enters a whole · psyche-belief › intent/design.md

::: comment
Each commit added one check without reading what the file already did. The symptom list names the knots; it lacks the move that avoids making one: reading the whole before adding to it.
:::

+ A change enters a whole. Before a line is added, the file is read for what it already does, and the line takes its place in that design or the design is redone; a file that grew by one line at a time, each added without reading the rest, is the accretion, and is rebuilt from its design.

### Proposal 3: A flake's checks · psyche-belief › vision/nix-builds.md

::: comment
The concrete rule for Nix: compiled work is shared, and a named check proves what the default does not.
:::

+ A flake's checks build the workspace once and run its tests in that build. A named check exists only for a proof the default check does not make, and it reuses the compiled work; a check that names a test the default already runs is the default, split.

### Proposal 4: A repeated instruction is a design decision · psyche-belief › vision/collaboration.md

::: comment
The named-check-per-proof rule was written into brief after brief and never judged. The routing line exists, a design decision goes up to Fable; what was missing is the recognition that a repeated instruction is one.
:::

+ An instruction a brief repeats is a design decision: it goes up to Fable the second time it is written, and comes back as a line in a module or not at all.
